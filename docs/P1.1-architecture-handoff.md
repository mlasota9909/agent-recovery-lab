## 9. Sequencing constraints that will break the matrix if ignored

P1 §9 still holds. P1.1 adds:

1. **A dirty working tree cannot produce a results row.** `git status --porcelain --untracked-files=all` against `$LAB_ROOT`. Commit or stash first. Runtime evidence is gitignored so it does not block this.

2. **Generate, then evaluate every arm, then generate the next incident.** Unchanged from P1. T1 destroys later ZFS snapshots on the shared dataset.

3. **Evaluate must not append catch-up onto a frozen ledger.** Unchanged: copy bytes, reset, stop consumer, restore bytes, then verify. If the on-disk `db.jsonl` already has catch-up (as at P1.1 close), restore `logs/review/X001/db.jsonl.frozen` *before* evaluate, or generate a new incident for P2/P3.

4. **Do not allocate a replacement replication slot** after `wal_removed`. Roll back to a T1/T2 snapshot that still contains the slot (`docs/runbook-slot-recovery.md`). Stop PostgreSQL before `lab-reset`.

5. **`lab-ready` is not a repair tool.** It only answers. Repair is the runbook, run deliberately.

6. **Analysis never reads `results/fixtures/`.** Live experimental rows will appear as `results/SC-01.jsonl` (etc.) from P3 onward.
