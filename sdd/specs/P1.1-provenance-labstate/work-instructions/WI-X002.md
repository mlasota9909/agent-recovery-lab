| **Blocks** | X003 |

## Objective

Make each results row's `harness_commit` name the exact harness state that produced it, and make it impossible to
produce a row from uncommitted code. This is the direct repair of defect D1 and the enforcement of Article XIV.

## Background (read before editing)

The shipped `bin/lab-evaluate-arm` assembles the results row with `"harness_commit": env("HARNESS_COMMIT_AT_P1_OPEN")`.
That env value is the commit recorded when P1 was opened at W001, not the commit of the code assembling the row. The
frozen results-row contract (`sdd/specs/P1-ground-truth-harness/contracts/results-row.md`) defines `harness_commit`
as the git commit of the harness that produced the row. You are aligning the implementation to the contract; you are
**not** changing the contract.

## Steps

1. In `bin/lab-evaluate-arm`, at the point the row is assembled:
   - compute `dirty = git -C "$LAB_ROOT" status --porcelain --untracked-files=all`;
   - if `dirty` is non-empty: write **no** results row, print the offending paths, exit non-zero with a clear message
     ("refusing to produce a results row: harness working tree is dirty; commit or stash the following paths"). Use a
     distinct, documented exit code;
   - otherwise compute `head = git -C "$LAB_ROOT" rev-parse HEAD` and set the row's `harness_commit = head`.
2. Remove the read of `HARNESS_COMMIT_AT_P1_OPEN` for this field. Do **not** delete the env key: it remains a valid
   record of the P1-open commit. Add a one-line comment at its definition in `etc/lab.env` (or the discover script
   that documents keys) stating it is P1-open provenance only and is **not** the source of any results-row field.
3. Validate the computed `harness_commit` against the schema's constraint (40 lowercase hex) before handing it to
   `bin/lab-results`; a non-conforming value is a hard failure, not a coerced one.
4. The dirty-tree check and the HEAD read must both target `$LAB_ROOT`, never the current working directory, so the
   result is independent of where the agent invoked the command from.
5. Do not change `bin/lab-results`, any contract, or the row's other fields. Do not regenerate the P1 null-run rows —
   those are quarantined in X003, not re-blessed here.

## Negative test (required)

Two parts.

**Dirty-tree probe.** Create an uncommitted change (a new untracked file, then separately a modification to a tracked
file). Assert **both** cause `lab-evaluate-arm` to refuse and write no row. A refusal that only catches modifications
but not untracked files is a fail — that is why `--untracked-files=all` is mandatory. Revert and confirm a row is
produced again.

**Wrong-source probe.** Temporarily re-point the field to `HARNESS_COMMIT_AT_P1_OPEN` in a scratch copy of the
script, produce a row on a clean tree whose HEAD differs from the P1-open commit, and assert X002-1's check now FAILS.
This proves the check would catch a regression back to the old behaviour. Restore the corrected script.

## Review bundle

Standard five, plus `row-clean.json`, `dirty-refusal.log`, `new-commit-row.json`, and `wrong-source-probe.log`.
