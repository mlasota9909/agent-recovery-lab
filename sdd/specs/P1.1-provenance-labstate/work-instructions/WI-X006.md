## Objective

Provide the tiered acceptance runner for P1.1, re-verify that no prior frozen contract changed, and update the
acceptance memo to record the remediation and that P1 was accepted only after P1.1.

## Steps

1. Build `bin/lab-verify-p1.1` that mechanically re-derives every P1.1 acceptance criterion (AC-P1.1-01..16) from
   live state or committed machine-readable artefacts, and prints, per criterion: id, tier, command, expected,
   observed, PASS/FAIL. It must print **per-tier totals separately** and a combined total, in the exact style of
   `lab-verify-p1`. It must not judge any criterion by searching prose (Article XIII). It must exit non-zero if any
   criterion fails.
   - AC-P1.1-03/04/05 must be re-derived by actually invoking `lab-evaluate-arm` against the open incident (clean and
     dirtied tree), not by reading X002's logs.
   - AC-P1.1-09/10 must be re-derived by running `lab-ready` against the live lab, and (for -10) against an induced
     unhealthy state that is then restored, leaving the lab healthy at the end.
   - AC-P1.1-16 is tier A: assert on machine-readable fields in the memo JSON, not on narrative.
2. Re-verify prior contracts by hash: the three P0 contracts against `logs/review/R007/contracts-unchanged.md`, and
   the two P1 contracts against their W002/W010 recorded hashes. Any mismatch is a hard FAIL. Record results in
   `logs/review/X006/contracts-unchanged.md`.
3. Confirm `set -a; source etc/lab.env; set +a; bin/lab-verify` is still 18/18 and `bin/lab-verify-p1` still 24/24.
4. Update `docs/p1-acceptance-memo.md`:
   - add a machine-readable block recording the three remediated defects (D1 provenance, D2 lab-state, D3
     planned-vs-completed), each with a boolean `closed: true` and the owning task;
   - add `accepted_only_after_p1_1: true`;
   - add `completed_arm_runs: 0`;
   - set `p2_recommendation` to `go` **only** if `bin/lab-ready` exits 0 at gate time; otherwise `blocked` with the
     failing condition. Do not hard-code `go`.
5. Update the checklist row for X006. Do not tick `Reviewed`.

## Negative test (required)

Two parts.

**Runner catches a real failure.** Temporarily re-point `harness_commit` in a scratch copy of `lab-evaluate-arm` back
to `HARNESS_COMMIT_AT_P1_OPEN` (or dirty the tree) and run `bin/lab-verify-p1.1`. Assert AC-P1.1-03/05 go **FAIL** and
the runner exits non-zero. Restore and confirm green. A gate that stays green through a reintroduced D1 is worthless.

**Recommendation is not hard-coded.** Induce an unhealthy lab (consumer stopped), run the memo-update path, and assert
`p2_recommendation` becomes `blocked`, not `go`. Restore readiness and confirm it returns to `go`.
