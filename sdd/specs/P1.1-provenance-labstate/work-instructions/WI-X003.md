# WI-X003 — Quarantine the P1 stub rows under `results/fixtures/`

| **Depends on** | X002 |

## Objective

Move every results row produced during P1 out of the live results path and into a clearly labelled fixtures area, so
that stub-verdict rows carrying the pre-fix `harness_commit` can never be mistaken for experimental data. The frozen
schema is not modified; quarantine is by location.

## Steps

1. Inventory every existing results file under `results/` (typically the P1 null-run output). For each, record path,
   line count, and the distinct `harness_commit`, `restore_verdict` and `consistency_verdict` values found. These
   should show the P1-open commit and `stub` verdicts — confirm that, and record it.
2. Create `results/fixtures/` (mode 0755). Move the P1 results file(s) there, preserving filenames, then set them
   0444 (they are immutable historical artefacts). Do not edit their contents.
3. Write `results/fixtures/MANIFEST.md` recording, per file: the prior path, the row count, why it is excluded
   (produced by the P1 null run with stub restore/consistency verdicts and a `harness_commit` bound to
   `HARNESS_COMMIT_AT_P1_OPEN` before the X002 fix), and the date of quarantine.
4. Establish the exclusion convention in code: whatever component will later aggregate results (there is none yet —
   do **not** build one) must read only `results/*.jsonl` and never `results/fixtures/`. Encode this as a documented
   glob in `etc/lab.env` (e.g. `RESULTS_GLOB=results/*.jsonl`) or in the results-row contract's companion doc if one
   exists — **without** modifying the frozen contract file. If `bin/lab-results` has a `validate --all` or discovery
   mode, update it to honour the glob and to refuse to treat `results/fixtures/` as live. If it does not, add a note
   for P3 and record it; do not build new machinery here.
5. Confirm that, after the move, no `results/*.jsonl` outside `results/fixtures/` contains any row.

## Negative test (required)

Place a syntactically valid one-row `results/_probe.jsonl` in the **live** path. Assert X003-1 now reports a non-zero
count (i.e. the check would catch a stray live row). Remove the probe and confirm X003-1 returns to 0. This proves the
"no live rows" assertion is real and not hard-coded to zero.
