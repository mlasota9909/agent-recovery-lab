## Objective

Establish, from the verbatim P6 completions, *why* Arm B returned a total null, and record the governance that follows.
This task produces no fix — it produces the evidence that tells J002/J003 what to fix, and the constitutional article
that says a null must be root-caused before it is reported. If this diagnosis is wrong, the rest of the tranche fixes
the wrong thing.

## Background (read before editing)

`logs/review/H009/headline.json` records `determinations:0, refusal_rate:1.0` for R0, R1 and R2. `logs/review/H009/`
also retains the raw completions (R0/R1/R2 × K = 15) and the assembled prompts. Three facts are already known and must
be reflected in the diagnosis, not rediscovered as if unknown: the context window is 262,144 tokens and R0 used 17,893
(not overflow); R0's content carried canonical hex LSNs (the exact form P6's prompt asked for) and still refused; R1/R2
content present integer LSNs and integer ranges respectively (not the requested hex form). Do **not** invent a cause —
classify only from what each completion actually says.

## Steps

1. Read the constitution; confirm seventeen articles in force. Append **Article XVIII** exactly as worded in `plan.md`
   (§ "Constitutional change"). Update the article count and any index.
2. Locate the 15 retained completions and their assembled prompts under `logs/review/H009/`. If a completion's verbatim
   bytes are not retained (only a hash), record that as a blocker — the diagnosis requires the raw text (Article XVIII
   demands primary evidence). Do not proceed on hashes alone.
3. Build `bin/lab-diagnose-refusal <completions-dir>` (or a one-shot script recorded in the bundle) that classifies
   each completion to exactly one proximate cause from this fixed taxonomy, by inspecting the verbatim bytes:
   - `grammar-noncompliance` — the model produced a coordinate-like answer but not in the tagged `COORDINATE: window=…
     lsn=…` form P6 required, so the extractor scored it a refusal;
   - `vocabulary-mismatch` — the model could not name the requested hex LSN because this representation's content does
     not contain it (integer LSN / range only);
   - `explicit-refusal` — the model emitted a `REFUSAL:` line on reasoning grounds despite a usable locator being
     present in content;
   - `task-infeasible-claim` — the model asserted the evidence is insufficient to localise a safe point;
   - `other` — none of the above; the completion text is quoted in full in the record.
   For each completion record: representation, replicate, the final tagged line (verbatim), a short quote of the
   deciding text, and the assigned cause. Emit `logs/review/J001/refusal-diagnosis.json` (canonical JSON, sorted keys).
4. Compute per-representation counts by cause; assert each representation's counts sum to K. Emit a small summary table
   in `refusal-diagnosis.md`.
5. Write the ADRs into the plan's decision record (or `logs/review/J001/adr.md` cross-linked from the plan):
   - **ADR-P6.1-1** — the null root cause, citing the per-representation counts and at least two verbatim completion
     quotes; state explicitly whether the cause is instrument (grammar/vocabulary) or genuine model inability, and if
     any completions are `task-infeasible-claim` even with a usable locator present, flag those as candidate genuine
     findings to re-test in J004.
   - **ADR-P6.1-2** — the containment topology correction (points to J002).
   - **ADR-P6.1-3** — the grammar/framing fix design (points to J003), justified by the counts in ADR-P6.1-1.
   - **ADR-P6.1-4** — corrected never weakened; the J004 re-run invalidates the prior null; the prior null is retained.
6. Commit. Update the checklist row for J001.

of the input, and confirm `bin/lab-diagnose-refusal` re-derives the original (byte-based) cause and does **not** honour
the hand-edited label — proving the classification is derived from the completion text, not copied from an annotation.
