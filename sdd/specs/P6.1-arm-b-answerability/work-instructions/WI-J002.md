## Objective

Correct the containment contract and its check so they assert what the cross-host deployment actually guarantees:
private-network endpoint, no public egress, pinned local alias, fixed weights. Do not pretend the runtime is loopback.
Do not mutate the frozen `model-runtime.md`.

## Background (read before editing)

`model-runtime.md` R2 says loopback-only / no outbound; H002 recorded `offline_verified:true`. The real path is LiteLLM
`http://c220m3:4001` → vLLM `gb10a:8000`. Read `model-runtime.amendment-1.md` (frozen in step 1) for the redefined
property R2a–R2d and the new record fields. The check must *test* egress, not assume it: the original check's flaw was
asserting a property (loopback) rather than observing the network behaviour.

## Steps

1. Freeze `model-runtime.amendment-1.md` under `contracts/`; hash-record in `logs/review/J002/`. Confirm the base
   `model-runtime.md` H001 hash still verifies (byte-identical).
2. Record the lab's private-address rule in `etc/lab.env` (e.g. `LAB_PRIVATE_CIDRS`, the known lab hosts `c220m3`,
   `gb10a`, and the forbidden cloud alias `deepseek-v4-pro`). Discover, do not guess; if a value is unknown, resolve it
   on the host and record it.
3. Rewrite the containment check (in `bin/lab-model`, or a dedicated `bin/lab-model-containment` that `bin/lab-model`
   calls) to verify, per invocation:
   - **R2a** endpoint host resolves to a private/lab address (`endpoint_is_private`);
   - **R2b** no connection to a public IP is observed during the invocation — observe with a stock tool (e.g. `ss`/`/proc`
     sampling of the invoking process's sockets, or `getent`/resolved address check on the connected peer); record
     `public_egress_observed`;
   - **R2c** the targeted alias is the pinned local alias, not `deepseek-v4-pro` (`alias_targeted`,
     `cloud_alias_targeted`);
   - **R2d** the loaded weights hash equals the H001-pinned `weights_sha256` (`weights_hash_matches_pin`).
   Set `containment_verified` true only when R2a–R2d all hold; echo the sub-check fields into the run record.
4. Run the check against the real pinned endpoint; capture `logs/review/J002/containment.json` with the sub-checks.
5. Commit. Update the checklist row for J002.

`deepseek-v4-pro`, run it, and confirm it exits non-zero naming the violated sub-check (`endpoint_is_private:false` or
`cloud_alias_targeted:true`). Revert and confirm `containment_verified:true` again. This proves the check tests egress
and alias, rather than assuming them. (AC-P6.1-06)
