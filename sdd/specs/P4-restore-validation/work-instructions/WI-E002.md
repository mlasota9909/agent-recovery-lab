# WI-E002 — `bin/lab-restore-db`: PITR to a target LSN into a sandbox cluster

| | |
| --- | --- |
| **Task** | E002 |
| **Phase** | B — The two restore layers |
| **Depends on** | E001 |
| **Blocks** | E004 |
| **Serves** | FR-2, AC-P4-02, AC-P4-03 |
| **Est.** | 4 h |

## Objective

Build `bin/lab-restore-db <incident> <lsn_int>` that reconstructs PostgreSQL to exactly the target LSN in a **new
sandbox cluster** (its own PGDATA and port) by replaying the host-side base backup + archived WAL, and never touches
the victim cluster.

## Background

The base backup and archived WAL for the incident live on the host, out-of-band, reachable via `archive/current`.
Standard PITR: restore the base backup into a fresh PGDATA, configure `recovery_target_lsn` = the target and
`recovery_target_action=promote` (or pause), start the sandbox cluster on a non-default port, let it replay to the
target, and confirm it stopped there. This is stock `pg_ctl`/recovery — no bespoke engine (Article V). The victim
cluster is never started, stopped, or written (ADR-P4-1).

## Steps

1. Resolve paths from `etc/lab.env`: base backup location, WAL archive (via `archive/current` for the incident),
   sandbox root `var/sandbox/<incident>/pgdata`, sandbox port (discover a free port; record it). Never guess.
2. Capture the victim PGDATA content hash **before** any action (a recursive hash of the victim cluster data dir).
3. Restore the base backup into the sandbox PGDATA. Write recovery settings: `restore_command` pointing at the host
   WAL archive, `recovery_target_lsn=<lsn_text>`, `recovery_target_inclusive=on`, `recovery_target_action=pause`.
4. Start the sandbox cluster on its own port. Wait for replay to reach the target and pause. Record
   `pg_last_wal_replay_lsn()`.
5. Confirm replay stopped at the target: `pg_last_wal_replay_lsn() <= target` and the first commit strictly beyond the
   target LSN is absent from the restored data (verify against a known post-target transaction from the ledger).
6. Capture the victim PGDATA content hash **after**; assert byte-identical to the before hash.
7. Emit `restore_target` fields (sandbox PGDATA, port) for the orchestrator. Leave the sandbox cluster running only if
   E004 will consume it immediately; otherwise stop it (never the victim) and record teardown. Idempotent: re-running
   detects an existing sandbox and reports `"changed": false`.

## Negative test (required)

Point `recovery_target_lsn` at an LSN **beyond** a known post-damage commit and confirm E002-3 detects that the
restored data now contains the beyond-target transaction (replay overshoot caught). Revert to the correct target ->
passes. Separately, attempt (in a scratch invocation) to start recovery against the victim PGDATA path and confirm the
script refuses with a non-zero exit and a stated reason before doing anything.

## Review bundle

Standard five, plus `replay-target.json`, `victim-untouched.txt`.

## Operator review checklist

- [ ] Restore produced a sandbox cluster on its own port, never the victim
- [ ] Victim PGDATA byte-identical before and after
- [ ] Replay stopped at exactly the target LSN; no beyond-target transaction present
- [ ] No `pg_ctl`/`systemctl` against the victim in the command log
- [ ] The overshoot negative was caught; the victim-path refusal fired
