## Objective

Build `bin/lab-verify-p4`, the tiered acceptance gate for P4: it re-derives every P4 criterion mechanically, prints
per-tier totals, is itself read-only over the evidence root (Article XVI), re-verifies all prior contract hashes and
runs `bin/lab-regression` against the pinned fixtures, and writes the P4 architecture handoff — recording the
walking-skeleton milestone and correctly stating what P5 and P6 build.

## Background

This gate certifies the loop-closing milestone. It follows the P3.1 discipline: the gate must not write anything under
the evidence root (proven with `bin/lab-gate-readonly-check`), and regression runs each prior gate against its own
pinned healthy fixture (not against the frozen P4 restore artefacts). Per-tier totals are mandatory; a single
undifferentiated total is prohibited (Article XIII).

## Steps

1. Implement `bin/lab-verify-p4` to re-derive AC-P4-01..AC-P4-19: parse the committed report/validation/promotion
   JSON and re-run the cheap mechanical checks (contract hashes; replay-target; victim-untouched manifests; skew
   resolution; verdict mapping on the four cases; promotion refusals; agreement; the ground-truth `correct` and the
   two discrimination cases). Label each M or A; print `TIER M p/n · TIER A p/n · TOTAL`.
2. Run `bin/lab-gate-readonly-check bin/lab-verify-p4` and assert the evidence-root manifest is byte-identical across
   the gate run (AC-P4-17).
3. Re-verify all prior contract hashes (incl. `capture-completeness.md` byte-identical) and run
   `set -a; source etc/lab.env; set +a` then each prior gate: `lab-verify` 18/18, `-p1` 24/24, `-p1.1` 16/16, `-p2`
   18/18, `-p2.1` 16/16, `-p3` 19/19, `-p3.1` 16/16; and `bin/lab-regression` green (AC-P4-18).
4. Write `docs/P4-architecture-handoff.md`: the restore mechanism (PITR into sandbox + `zfs clone`), the observed
   cross-layer skew, the loop-closing result (ground-truth -> correct), the discrimination outcomes, the
   walking-skeleton milestone reached, and an explicit forward note: **P5 builds representations R0/R1/R2 and P6 builds
   the Arm B model harness; P5/P6 reuse this restore+validate harness unchanged.** Do not copy P4's anti-goals forward
   as if they were P5's scope (anti-goal-inversion guard). Assert the handoff on machine-readable fields.
5. Update `checklist.md` (E010 row). Do not tick `Reviewed`.

## Negative test (required)

Two faults, each caught then reverted: (1) temporarily corrupt one prior contract (append a byte to a scratch copy the
gate reads) and confirm `bin/lab-verify-p4` goes red on the hash re-verification — proving prior-hash checking is live.
(2) Add a line to `bin/lab-verify-p4` that writes a marker file under the evidence root and confirm
`bin/lab-gate-readonly-check` catches the write (Article XVI). Revert both -> green.
