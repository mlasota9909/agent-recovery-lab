## Objective

Build `bin/lab-promote <incident> <restore_of> [--authorize <token>]` that enforces the `promotion-gate.md` contract:
it refuses unless the verdict is `correct` AND an explicit authorization token is supplied, and in this lab it performs
a **logged simulation only** — never overwriting the victim or evidence.

## Background

Promotion is the destructive step in a real deployment (cut the live system over to the restored state). The whole
point of the gate is that it can never happen by accident or on a bad verdict. Two independent gates: a `correct`
verdict (R2) and an explicit token the operator supplies (R3, never inferred). In the lab, even a clean+authorized
request is simulated (R4): it records what it *would* replace and does nothing destructive. Validation (E005/E006)
never calls this path (R1).

## Steps

1. Read `report.json` (E006). If `consistency_verdict != correct`, refuse (non-zero exit, reason
   "verdict not correct") and leave `promotion.decision=withheld`.
2. If no `--authorize <token>` is supplied, refuse (non-zero exit, reason "no authorization token") and leave
   `promotion.decision=withheld`.
3. With a `correct` verdict AND a token: record `decision=simulated`, write a `simulation` block describing what would
   be replaced (`would_replace`), take **no** destructive action, and record `action_taken` stating the victim and
   evidence were untouched. Never emit `decision=authorized` in the lab (R4).
4. Capture the victim+evidence manifest before and after the promote call; assert byte-identical (a simulation changes
   nothing). Emit the promotion record per `promotion-gate.md` §4.
5. Idempotent; refuses on a dirty tree if it writes any provenance/results-bearing artefact (Article XIV).

## Negative test (required)

Modify `bin/lab-promote` to promote on any verdict when a token is present (drop the R2 verdict gate); confirm E007-1
now wrongly proceeds and the check catches it. Revert -> refuses. Separately, modify the simulation to actually
`zfs rollback`/overwrite the victim and confirm the E007-4 manifest check catches the victim mutation. Revert -> victim
untouched. This proves both gates and the simulation-only rule are enforced, not asserted.

## Review bundle

Standard five, plus `gate-cases.md`.

## Operator review checklist

- [ ] Promotion refuses without a `correct` verdict
- [ ] Promotion refuses without an explicit token
- [ ] A clean+authorized promotion is `simulated` only; `authorized` is never emitted in the lab
- [ ] Validation alone leaves `promotion.decision=withheld`
- [ ] The manifest is byte-identical across the promote call
- [ ] Both negatives fired (bad-verdict promote; destructive simulation), then reverted
