## Objective

Freeze `restore-report.md` (the validation verdict record) and `promotion-gate.md` (the validate-vs-promote boundary),
and record the P4 entry gate: `bin/lab-ready` exit 0, a target SC-01 incident that has passed `bin/lab-ledger-account`
exactly-once, and the coordinate(s) to be restored having `arm_no_peek_ok` true. No restore code is written until these
shapes are fixed.

## Background

Both contracts ship in this package under `sdd/specs/P4-restore-validation/contracts/`. E001 does not author them — it
validates them, hash-freezes them into the review bundle, and proves the entry gate holds. The load-bearing rules are
the safety block (`restore-report.md` R6: victim+evidence byte-identical before/after) and the promotion gates
(`promotion-gate.md` R2 clean verdict, R3 explicit token, R4 lab simulation only).

## Steps

1. Confirm both contract files exist and are well-formed markdown with the schema tables and an example JSON that
   parses. Parse each fenced `json` block with `python3 -m json.tool` and confirm success.
2. Record the SHA-256 of each contract into `logs/review/E001/contract-hashes.txt` in the prior-tranche format
   (`<sha256>  <path>`), so future gates re-verify them byte-identical.
3. Verify and record the entry gate:
   - `set -a; source etc/lab.env; set +a; bin/lab-ready; echo "lab-ready exit=$?"` -> capture exit 0.
   - Identify the reconciled SC-01 incident (from P3) and run `bin/lab-ledger-account <incident>`; capture
     `gaps=0, duplicates=0` and exit 0.
   - Read the Arm A and naive `arm-coordinate` records for that incident and confirm each has
     `selection_inputs.read_injection_log=false`, `read_oracle_optimum=false`, `read_provenance=false`.
   - Write all facts into `logs/review/E001/entry-gate.json`
     (`{"lab_ready_exit":0,"reconciled_incident":"<id>","gaps":0,"duplicates":0,"arm_a_no_peek_ok":true,"naive_no_peek_ok":true}`).
4. Confirm the contracts do not contradict FROZEN `results-row.md`: `restore-report.coordinate` fields
   `lsn_text`/`lsn_int`/`snapshot` map onto `recovery_coordinate.*`. Record the mapping in
   `logs/review/E001/results-row-alignment.md`.

## Negative test (required)

Copy `promotion-gate.md` to a scratch file and change R2 so promotion is allowed on any verdict; run a validator that
asserts the frozen file still forbids promotion unless verdict==correct. Assert the validator flags the scratch
mutation, and that the real file's hash is unchanged. Revert (delete scratch) -> clean.
