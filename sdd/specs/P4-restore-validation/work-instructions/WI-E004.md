## Objective

Build `bin/lab-restore <incident> <coordinate.json>` that resolves a single coordinate to (LSN, snapshot), drives
`bin/lab-restore-db` and `bin/lab-restore-fs` to that coordinate, records the cross-layer skew, and assembles the
report skeleton (everything except the validation results and verdict, which E005/E006 fill).

## Background

A coordinate names one LSN. The DB restores to exactly that LSN; the filesystem can only restore to a snapshot
boundary, so it restores to the **newest snapshot with `lsn_int <= target`** (via `bin/lab-coordinate`, ADR-008). The
residual gap between the snapshot's LSN and the target LSN is the **cross-layer skew**, recorded in
`coordinate.skew_ms` — a measured quantity, not something to engineer to zero (ADR-P4-5). Integer LSN arithmetic only.

## Steps

1. Read the coordinate JSON (`lsn_text`, `lsn_int`, and for arm coordinates the `selection_inputs`). If it is an arm
   coordinate, assert `arm_no_peek_ok` (refuse otherwise, ADR-P4-6). If it is labelled `ground_truth`, skip the
   no-peek check and set `restore_of=ground_truth`.
2. Resolve the snapshot: `bin/lab-coordinate` -> newest snapshot with `lsn_int <= target`. Compute
   `skew_ms` = |wall_clock(target) - wall_clock(snapshot boundary)| from the heartbeat index.
3. Capture the whole-of-victim-plus-evidence manifest hash **before** (delegated to the shared manifest helper; see
   E008 — E004 records it so E005/E006 can carry it into the report).
4. Call `bin/lab-restore-db <incident> <lsn_int>` and `bin/lab-restore-fs <incident> <snapshot>`.
5. Assemble the report skeleton: `incident_id`, `restore_of`, `coordinate` (with `skew_ms`), `restore_target`,
   `selector_provenance`, and the `safety.manifest_before`. Write it to
   `var/restore/<incident>/<restore_of>/report.partial.json`.
6. Idempotent and non-destructive to the victim. Include a `--teardown` that destroys the sandbox cluster + clone for
   this restore (never the victim).

## Negative test (required)

Force the snapshot resolver to use string comparison (so `3/9` sorts after `3/10`) and confirm E004-2 fails (wrong
snapshot chosen); revert to integer arithmetic -> passes. This is the LSN-ordering trap that has bitten the project.

Standard five, plus `skew.json`, and the `report.partial.json` path noted in `artefacts.md`.
