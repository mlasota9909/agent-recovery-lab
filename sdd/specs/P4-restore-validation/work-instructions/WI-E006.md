## Objective

Build `bin/lab-verdict <incident> <restore_of>` that reads the E005 validation block and emits exactly one of the four
fixed verdicts (`correct` / `incorrect-safe` / `incorrect-corrupt` / `not-recovered`) per `restore-report.md` §5, then
assembles the full restore report by merging the E004 skeleton, the E005 validation block, the verdict, and the
`safety.manifest_after`.

## Background

The verdict is a deterministic function of the validation results (ADR-P4-4), not a judgement call:

- zero mismatches -> `correct`
- only `legit_lost` mismatches (no damage retained), internally consistent -> `incorrect-safe`
- any `damage_retained` mismatch, or an internally inconsistent instance -> `incorrect-corrupt`
- no usable/consistent instance produced (replay failed, clone failed, cluster would not start) -> `not-recovered`

The full report must then conform to `restore-report.md` and carry a `harness_commit` computed at report time on a
clean tree (Article XIV).

## Steps

1. Read `validation.json` (E005) and `report.partial.json` (E004).
2. Apply the §5 mapping deterministically to compute `consistency_verdict`.
3. Capture the whole-of-victim-plus-evidence manifest hash **after** and set `safety.manifest_after`; set
   `safety.victim_untouched` / `evidence_untouched` = (`manifest_after == manifest_before`).
4. Set `promotion` to the validation-only default: `decision=withheld`, `clean_verdict = (verdict==correct)`,
   `authorized_by=null`, `simulated=false` (E007 owns changing this).
5. Assert the git tree is clean; compute `harness_commit = git rev-parse HEAD`; refuse to write the report on a dirty
   tree (Article XIV).
6. Write the full report to `var/restore/<incident>/<restore_of>/report.json` and validate it against
   `restore-report.md` (all required fields, correct types). Deterministic: two runs byte-identical.

## Acceptance tests

| ID | Tier | Command | Expected |
| --- | --- | --- | --- |
| E006-1 | M | feed a zero-mismatch validation block | verdict `correct` (AC-P4-09) |
| E006-2 | M | feed a legit-lost-only block; feed a damage-retained block; feed a no-instance block | `incorrect-safe`; `incorrect-corrupt`; `not-recovered` respectively (AC-P4-09) |
| E006-3 | M | run twice on the same input | `report.json` byte-identical (deterministic) |
| E006-4 | M | validate `report.json` against `restore-report.md`; check `harness_commit` | schema-valid; `harness_commit` equals `git rev-parse HEAD` on a clean tree (AC-P4-10) |

## Negative test (required)

Two faults, each caught then reverted: (1) make the verdict mapping treat a `damage_retained` mismatch as `correct`;
assert E006-2 fails (a damaged restore is called correct) — proving the mapping is load-bearing. (2) Make a change to
leave the tree dirty and confirm E006-4 refuses to write the report (Article XIV), then commit/clean -> passes.

## Review bundle

Standard five, plus `verdict-cases.md`.

## Operator review checklist

- [ ] The four verdicts map exactly per contract §5, with no case collapsed into another
- [ ] `damage_retained` can never yield `correct`
- [ ] The report is schema-valid and deterministic
- [ ] `harness_commit` is HEAD on a clean tree; a dirty tree is refused
- [ ] Both negatives fired, then reverted
