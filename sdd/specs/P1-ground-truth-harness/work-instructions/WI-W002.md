## Objective

Install the two contracts shipped with this package into the repo as frozen artefacts, hash-record them, and confirm
they are internally consistent with P0's frozen coordinate contract. **Write no implementation code in this task.**

## Why this is a separate task, ahead of any code

ADR-P1-1: every quantitative result is a field in the results row. A field added after runs have started
makes earlier rows incomparable and forces a re-run of everything already run. The contract is therefore frozen before
a single line of harness code exists, so that the code is written to the contract rather than the contract being
retro-fitted to whatever the code happened to emit.

This is the task the operator reads line by line.

## Steps

1. Confirm the two contract files are present at
   `sdd/specs/P1-ground-truth-harness/contracts/results-row.md` and `.../ledger-integrity.md`. They ship with this
   package; you are not authoring them from scratch.
2. **Consistency review against P0.** Read `sdd/specs/P0-lab-substrate/contracts/coordinate.md` and verify:
   - every coordinate object in the results row requires exactly the six fields the frozen coordinate contract defines;
   - no field name collides with a different meaning;
   - the LSN arithmetic rule (`(high << 32) + low`, never string comparison) is stated identically in both.
   Record the comparison. If you find a genuine inconsistency, **stop and report it** — do not silently reconcile.
3. **Enumerate the field set** into a machine-readable schema at `etc/results-row.schema.json`, derived from the
   contract's tables. This is the artefact the W003 validator consumes, so it must be generated from the contract, not
   hand-typed independently of it. Include for every field: name, JSON type, nullable, and where the contract states a
   range or enum, the permitted values.
4. Record SHA-256 of both contracts and of the generated schema in `logs/review/W002/contract-hashes.json`. W010
   re-verifies these to prove nothing drifted during the tranche.
5. Append to `etc/lab.env`: `RESULTS_SCHEMA` (path to the generated schema), `RESULTS_FILE_MODE=0444`,
   `BARRIER_TIMEOUT_S=120`.
6. Do **not** create `bin/lab-results`, `bin/lab-ledger-verify` or any other executable in this task.

## Negative test (required)

Take the contract's example row, mutate it three ways in a scratch copy, and confirm the generated schema **rejects**
each: (a) delete a required field, (b) replace an integer with a quoted string, (c) set an enum field to a value
outside its permitted set. Capture all three rejections. If any mutation validates, the schema does not faithfully
express the contract and this task is not done.
