## Objective

Build `bin/lab-results`: the only component permitted to write a results row. It validates against the frozen schema,
appends, and makes closed files immutable.

## Steps

1. `bin/lab-results append --file <path> --row <json|->`:
   - validates the row against `${RESULTS_SCHEMA}`;
   - **refuses to coerce.** A quoted `"5"` where an integer is required is a failure, not a cast. A missing required
     field is a failure, not a null;
   - enforces contract validation rules 3 through 8, specifically:
     - `arm=model` requires `model_id` and `representation` in `R0..R2`;
     - `arm` in `stub|deterministic|naive` requires `representation=none`;
     - null `chosen_coordinate` requires all coordinate-error and outcome-error fields null;
     - `restore_verdict=correct` requires `damage_rows_retained=0` **and** `legit_rows_lost=0`; any other combination
       is a contradiction and fails;
     - in P1, `restore_verdict` and `consistency_verdict` must both be `stub`;
   - enforces the **cross-row invariant**: if the file already contains rows with this `incident_id`, the incoming
     `ground_truth_coordinate` must be **byte-identical** to theirs. On mismatch, refuse the row and exit non-zero.
     This is the guard that makes AC-P1-17 meaningful rather than incidental;
   - appends exactly one line, then fsyncs;
   - prints the accepted row's `run_id` as JSON.
2. `bin/lab-results validate --file <path>` re-validates every row in a file and reports per-row results plus totals.
3. `bin/lab-results close --file <path>` sets mode 0444. Appending to a closed file must fail with a clear message
   naming the file, not a permission traceback.
4. Byte-identity comparison for the cross-row invariant must be on **canonical JSON** (sorted keys, no insignificant
   whitespace), so that key ordering does not create false mismatches. State the canonicalisation you used.
5. Do not implement any analysis, scoring or coordinate computation here. This component writes rows; it does not
   produce their values.

## Negative test (required)

Two parts, both mandatory.

**Coercion probe.** For every numeric field in the schema, submit a row where that field is a quoted string. Assert
**every** submission is refused. A validator that coerces even one field silently converts a bug into a plausible
number, which is the failure class this whole tranche exists to prevent. Record the per-field result.

**Immutability probe.** After `close`, attempt an in-place edit with a text tool and with a direct write. Assert both
fail and the file's SHA-256 is unchanged afterwards.

## Review bundle

Standard five, plus:
- `validation-cases.json`
- `coercion-probe.json` — one entry per numeric field, with the rejection
- `immutability-probe.log` — the failed edit attempts plus before/after hashes
- `canonicalisation.md` — how canonical JSON is computed for the cross-row comparison

## Operator review checklist

- [ ] No field is ever coerced; the per-field coercion probe is complete
- [ ] Cross-row ground-truth invariant is enforced on append, not merely checked later
- [ ] `restore_verdict=correct` is impossible to write in P1
- [ ] Closed files are 0444 and appends to them fail loudly
- [ ] Canonicalisation is documented, so byte-identity is well defined
