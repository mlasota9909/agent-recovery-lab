## Objective

Build `bin/lab-inject`: the scripted damage for SC-01, executed as `lab_agent`, recording exactly what it did and at
which commit LSN, so the oracle can compute the optimum without guessing.

## Scenario SC-01, restated

| | |
| --- | --- |
| Damage class | database data |
| Timing pattern | near-instant |
| Difficulty tier | 1 (vertical slice) |
| Archetype | An agent issues a destructive bulk delete against a production table, for example clearing a table it misread as scratch. Represents the destructive database write failure mode (Ruan et al., 2024) and agent tool-call irreversibility (Naihin et al., 2023). |
| Injection | A single transaction issuing a broadly-qualified `DELETE` against `orders`, committed as the agent principal at a recorded LSN. |
| Optimum | The commit LSN of the last legitimate transaction **before** the malicious DELETE. |

The citation column is not decoration. It links the scenario to the documented failure mode it reproduces, and it
belongs in the recorded artefact.

## Steps

1. `bin/lab-inject --scenario SC-01 [--rows <n>]`:
   - connects as **`lab_agent`** using the `lab_agent` role;
   - issues one transaction containing a broadly-qualified `DELETE` against `orders`;
   - records the commit LSN authoritatively immediately after commit;
   - is deterministic in *what* it destroys given the same seed and predicate, so replicates are comparable.
2. Write `${EVIDENCE_ROOT}/<scenario>/<incident>/injection.json` containing, at minimum:
   - the SQL executed, **verbatim**;
   - the principal (`lab_agent`), the commit LSN, the commit wall clock;
   - the count of rows destroyed, and their identifiers;
   - the scenario id, damage class, timing pattern, and the archetype citation string.
3. **Timing requirement (AC-P1-09).** The injection must occur while the legitimate workload is running, and the
   harness must be able to demonstrate at least one legitimate commit within 2 s **before** and one within 2 s
   **after** the malicious commit. Provide a `--verify-timing` mode that asserts this against the workload manifest and
   exits non-zero if the window is not satisfied. This is what makes "just restore earlier" costly and the problem
   non-trivial.
4. `lab_agent` must hold exactly the privileges needed to perform this delete and no more. Record the observed grants.
5. Do **not** grant the injector any access to the evidence store, the archive or the results store. If it can reach
   them, P0's isolation is broken and this task must stop and report.
6. Do not implement SC-02, SC-03 or SC-04 damage. One scenario only.

## Negative test (required)

**Timing-window enforcement must be able to fail.** Run an injection deliberately *after* stopping the workload, so no
legitimate commit follows it, and confirm `--verify-timing` exits non-zero. Then re-run correctly with the workload
live and confirm it passes. A timing check that always passes would let a trivially-easy incident masquerade as a valid
one, and every result derived from it would flatter the method.

## Review bundle

- `grants.json`
- `isolation-recheck.log` — the W006-7 refusals, per principal per path
- `determinism-two-runs.md` — the identical destroyed-row sets
