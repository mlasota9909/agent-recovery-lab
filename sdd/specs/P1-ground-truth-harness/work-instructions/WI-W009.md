## Objective

Measure what a run actually costs now, and convert that into a measured, stratified sample-size plan that replaces an
open-ended sample target.

## Why the inherited number must not be reused

P0's T015 measured a full cycle at **49.335 s**, implying roughly 583 cycles in 8 hours. That figure predates P0.1's
reset guard, which now **refuses to roll back while PostgreSQL is running**. The automated cycle must therefore stop the
cluster, roll back, and restart it. The real cost is higher, and the inherited figure is optimistic.

That number replaces *"the maximum achievable sample will be attempted"*, which is not a plan. It must be measured,
not inherited.

## Steps

1. `bin/lab-throughput --phase generate|evaluate --repeats <n>`:
   - measures wall-clock cost of each phase separately, because they have very different costs and the matrix is
     dominated by arm evaluations;
   - **at least 5 repeats** per phase; report median, min, max and standard deviation. A single measurement is not a
     measurement;
   - breaks each phase down by step (reset, barrier, workload, snapshot, inject, capture, oracle, analysis, results
     append) so a future bottleneck is diagnosable;
   - records host conditions: load average, whether anything else was running;
   - writes `docs/throughput.json`.
2. Measure `evaluate-arm` under **tier t2**, since that is the tier arms actually use, and t2 is expected to be far
   cheaper than t1 or t0. If it is not, say so — that finding changes the plan.
3. Derive `docs/sample-size-plan.md` from the measured numbers. It must state:
   - the design space: damage classes × timing patterns, and which cells P1..P8 will actually cover;
   - **per-cell replicate count** and the arithmetic that produces the total;
   - separate counts for incidents generated versus arms evaluated, since one incident serves many arms:
     `total_arm_runs = incidents × representations × replicates`;
   - the time budget in hours, using the **median** for planning and the **worst case** for the risk statement;
   - an explicit descope ladder: which cells are dropped first if time runs short, and the statement that SC-01 and
     SC-02 with the full R0/R1/R2 ablation constitute a complete result on their own.
4. Emit the plan's key figures as machine-readable JSON fields inside `docs/throughput.json` (total incidents, total arm
   runs, planned hours, median seconds per phase) so AC-P1-22 asserts on fields rather than prose, per Article XIII.
5. Do **not** run the matrix. This task sizes it.

## Negative test (required)

**A single measurement must be refused.** Invoke `lab-throughput --repeats 1` and confirm it exits non-zero with a
message stating that a median requires multiple repeats. A tool that reports a median of one sample invites exactly the
kind of confident-but-unfounded number that the inherited 49.335 s turned out to be.

## Review bundle

Standard five, plus:
- `throughput.json`
- `sample-size-plan.md`

- [ ] The delta against the inherited 49.335 s is stated numerically
- [ ] Plan states per-cell replicates and the arithmetic reproduces the total
- [ ] Incidents and arm runs are counted separately
- [ ] Descope ladder present, with SC-01 + SC-02 + full ablation named as a complete result
- [ ] "As many as possible" appears nowhere
