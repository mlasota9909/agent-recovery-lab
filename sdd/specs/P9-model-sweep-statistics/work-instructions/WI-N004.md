# WI-N004 — Execute the cross-model sweep

## Goal
Generate the paired evidence: SC-01 [and SC-02 if scope=both] x R0/R1/R2 x 3 models x K=5,
through the guarded interface, scored via the unchanged P4 restore+validate path.

## Steps
1. For each (scenario, representation, model, replicate) cell:
   a. Build the guarded model_view for (scenario, representation).
   b. Run inference (greedy, fixed seed) on the model; capture the raw completion.
   c. Extract the coordinate deterministically; a "cannot determine" completion is
      recorded as a REFUSAL (Article VIII) — never coerced.
   d. For determinations: score through the P4 path against the frozen oracle; record
      verdict, damage_rows_retained, legit_rows_lost, and skew.
   e. Append a results row (unchanged P1 schema) AND a `results/sweep-runs.jsonl` sidecar
      record carrying {results_row_id, sweep_id, scenario, representation, model_alias,
      model_family, tokenizer_id, replicate_index, outcome}.
2. Make the runner RESUMABLE (idempotent per cell id) and record run_failure rows for any
   cell that cannot proceed, so the batch continues (Article XIX).
3. Enforce the P1 ledger-idempotency guard across any reset boundary (no duplicated LSN
   within an incident; ledger range contained by incident open/close).
4. Write `logs/review/N004/sweep-completeness.json`:
   {planned, determinations, refusals, run_failures, rows==planned}.

## Acceptance tests
- AC-P9-06: rows == planned; partition recorded; determinations carry a P4 verdict;
  refusals retained; SC-01 banked ledger + banked results byte-identical afterward.

## Negative test
- Drop one sidecar row to inflate the determination share; prove the completeness/join
  check catches the mismatch (rows != planned OR sidecar/results id-join gap). Restore.

## Review bundle -> logs/review/N004/
- sweep-completeness.json, a sample raw completion per (representation,model), the
  idempotency-guard transcript, banked-artefact byte-identical proof, tier line.
