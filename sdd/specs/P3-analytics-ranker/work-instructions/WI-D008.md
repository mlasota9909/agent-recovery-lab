## Objective

Connect the two arms to the P1 `evaluate-arm` phase so that, for the SC-01 incident, running each arm produces a
chosen coordinate, the P1 oracle scores it, and a complete schema-valid results row lands automatically — with
recovery-point error in both LSN and rows/bytes — for `arm_a` and for `naive`.

## Background

P1 already owns `evaluate-arm` (reset to `--tier pre-disaster`/`--tier post-disaster`, run the arm's selector,
restore-or-score, append a results row) and the oracle that computes recovery-point error against the known optimum.
D008 supplies the selector step for `arm_a` (`bin/lab-rank`) and `naive` (`bin/lab-naive`), passes the arm coordinate
into the oracle scoring, and confirms the row is complete. The oracle — not the arm — reads provenance and the
injection log to compute error; the arm never does. The dirty-tree guard (Article XIV) means the tree must be clean
before a row is written.

## Steps

1. Register `arm_a` and `naive` as selectable arms in `evaluate-arm`, each invoking its D006/D007 binary and handing
   the resulting `arm-coordinate` record to the oracle scorer.
2. Reject any arm coordinate whose `selection_inputs` has a peek flag `true` (contract §4) before scoring — fail loud.
3. Run `evaluate-arm` for both arms against the same SC-01 incident id (ADR-005 fixed incident), appending two
   results rows that differ in `arm`, `chosen coordinate`, and the oracle-computed errors.
4. Confirm each row is schema-valid against `results-row.md` and carries recovery-point error in **LSN** and in
   **rows/bytes**, plus `harness_commit` = `git rev-parse HEAD` (clean tree).

## Negative test (required)

Dirty the working tree (touch a tracked file) and attempt an `evaluate-arm` run; assert it refuses to write a results
row (Article XIV / P1.1 guard) and exits non-zero. Commit/stash and confirm the row is written with `harness_commit` =
current HEAD. A results row written from a dirty tree is a fail.
