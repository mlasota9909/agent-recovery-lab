# WI-D004 — mean+3σ anomaly scoring against the declared quiescent baseline

## Objective

Score each analytics window for anomaly using mean+3σ computed against the **declared quiescent baseline window**
recorded in the incident manifest (a window that predates injection), so the SC-01 deletion window scores anomalous
and a quiescent window does not. The baseline is fixed before the damage is seen — never fitted to it.

## Background

Anomaly detection here is deterministic statistics, not learning (Article I). The baseline window is declared in
`etc/scenarios/sc01.env` and in the incident manifest by D002, and it predates `pre_injection`. For each metric
(burst density, deletion volume, per-relation churn), compute mean μ and standard deviation σ over the baseline
windows; a window's anomaly score is the max standardised deviation `(x − μ)/σ` across metrics, and it crosses
threshold at ≥ 3. Reading the baseline from the manifest — not recomputing it from the whole incident — is what keeps
the scoring non-circular.

## Steps

1. Extend the analytics output (or add `bin/lab-anomaly <incident>`, your choice, but keep it a thin layer over
   D003's `analytics.jsonl`) to attach an `anomaly_score` and `anomalous` boolean to each window.
2. Read the baseline window bounds from the incident manifest / scenario config. Assert the baseline predates the
   injection damage window from `injection_log.json` (fail loud if it overlaps).
3. Compute μ, σ per metric over baseline windows only; score every window; write `anomaly.jsonl`.
4. Confirm the SC-01 deletion window (the one spanning the injection damage window) is `anomalous=true`, and a named
   quiescent window is `anomalous=false`.

## Negative test (required)

Set the baseline window to one that **overlaps** the injection damage window (fitting the baseline to the damage);
assert the tool refuses and exits non-zero (D004-1's precondition fails loud), because a baseline contaminated by the
damage would understate the anomaly. Restore the correct pre-injection baseline and confirm scoring passes. A scorer
that silently accepts a damage-contaminated baseline is a fail.

## Review bundle

Standard five, plus `anomaly.jsonl`, `baseline-window.json`, `threshold-check.md`.

## Operator review checklist

- [ ] The baseline window provably predates the injection damage window
- [ ] The SC-01 deletion window scores anomalous (≥ 3σ)
- [ ] A quiescent window scores below threshold
- [ ] Scoring is deterministic across two runs
- [ ] The contaminated-baseline negative test was refused, then passed after revert
