## Objective

Freeze `candidate-coordinate.md` (what the analytics layer emits per candidate) and `arm-coordinate.md` (the single
shape every arm returns), and record the P3 entry gate: `bin/lab-ready` exit 0 and a target incident that has passed
`bin/lab-ledger-account` exactly-once. No producer code is written until these shapes are fixed.

## Background

Both contracts ship in this package under `sdd/specs/P3-analytics-ranker/contracts/`. D001 does not author them — it
validates them, hash-freezes them into the review bundle, and proves the entry gate holds. The load-bearing rules are
provenance-blindness (candidate R1, arm R5) and the no-peek `selection_inputs` audit block (arm §4). Everything
downstream is held to these.

## Steps

1. Confirm both contract files exist and are well-formed markdown with the schema tables and the example JSON that
   parses. Parse each fenced json code block (the `json` examples) with `python3 -m json.tool` and confirm it succeeds.
2. Record the SHA-256 of each contract into `logs/review/D001/contract-hashes.txt` in the same format prior tranches
   used (`<sha256>  <path>`), so future gates re-verify them byte-identical.
3. Verify the entry gate and record it:
   - `set -a; source etc/lab.env; set +a; bin/lab-ready; echo "lab-ready exit=$?"` → capture exit 0.
   - Identify a reconciled incident (a P2 generic incident is acceptable as the gate witness) and run
     `bin/lab-ledger-account <incident>`; capture `gaps=0, duplicates=0` and exit 0.
   - Write both facts into `logs/review/D001/entry-gate.json` as machine-readable fields
     (`{"lab_ready_exit":0,"reconciled_incident":"<id>","gaps":0,"duplicates":0}`).
4. Confirm the contracts do not contradict the FROZEN `results-row.md`: the `arm-coordinate` fields
   `lsn_text`/`lsn_int`/`wall_clock`/`snapshot` must map onto `recovery_coordinate.*`. Record the field mapping in
   `logs/review/D001/results-row-alignment.md`.

## Negative test (required)

Copy `arm-coordinate.md` to a scratch file, add a `principal` field to the schema table, and run a validator that
greps the schema for forbidden provenance fields; assert it reports a violation and exits non-zero. Delete the scratch
file and confirm the real contract passes. A contract validator that cannot flag a provenance field in a candidate/arm
record is a fail.
