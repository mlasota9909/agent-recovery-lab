## Objective

Implement the simple, readily understood baseline: select the last checkpoint before an approximate operator-supplied incident
time, offset by a **declared, fixed** time error read from scenario config, and emit an `arm-coordinate` record with
`arm=naive`. The error parameter is never tuned to disadvantage the comparator.

## Background

The naive comparator represents what an operator does today: "roll back to just before roughly when I think it went
wrong." The roadmap requires it in every run and requires deliberate, declared error in that approximate time (real
operators do not know the exact incident instant). ADR-P3-3: the error is a fixed parameter in `etc/scenarios/sc01.env`
and is recorded in `selection_inputs.incident_time_error_seconds`, so the comparison is honest and reproducible.

## Steps

1. Build `bin/lab-naive <incident>`: read the approximate incident time and the declared error from scenario config,
   compute `approx = t_incident_estimate + declared_error`, resolve the last snapshot/checkpoint with wall-clock ≤
   `approx` (integer-LSN resolution via `bin/lab-coordinate`), and emit one `arm-coordinate` record with `arm=naive`,
   `chosen_candidate_id=null`, `selector_version` = the comparator version, and a `selection_inputs` block recording
   `approx_incident_time`, `incident_time_error_seconds`, and all three peek flags `false`.
2. The rationale is a fixed template ("last checkpoint before operator-estimated incident time + declared error").
3. Confirm the error is read from config, not computed from the injection log or oracle (which the comparator must not
   read either).
4. Prove determinism: run twice, `diff` → identical.

## Negative test (required)

Change the declared error in scenario config to a different fixed value and assert the naive coordinate moves
accordingly and `selection_inputs.incident_time_error_seconds` reflects the new value — proving the error is honestly
sourced from config and recorded, not hard-coded or hidden. Restore the original value. A comparator whose recorded
error does not match its config is a fail.
