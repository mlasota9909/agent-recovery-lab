## Objective

Build `bin/lab-repr-query`, the single query interface that answers the fixed probe set (`representation-interface.md`
§5) for R0, R1 and R2 through **one** request/response envelope. For a given probe and incident the `answer` schema is
identical across the three representations; only `content` and `telemetry` differ. Responses are deterministic on
re-run.

## Background

This is the surface P6's model talks to. Its correctness is the ablation's correctness: if the envelope or probe set
differs across representations, P6 is confounded. The interface is a pure function of (representation artefact, probe,
params) — read-only, no mutation, no model, provenance-blind. Each representation answers a probe from its own artefact
(R0 from the flat log, R1 from windows, R2 from graph+summaries), but returns the same envelope. `content` is the
evidence that representation surfaces; `telemetry.evidence_bytes` is the exact UTF-8 byte length of `content`.

## Steps

1. Implement the request/response envelope exactly per `representation-interface.md` §3-4. Validate every request
   (`incident_id`, `representation` in {R0,R1,R2}, `probe_id` in the fixed set, `params`), rejecting unknown probes.
2. For each of the six probes, implement the answer from each representation's artefact so the `answer` object matches
   the frozen per-probe schema (§5) identically across R0/R1/R2. Integer LSN only for any window bound/coordinate.
3. Populate `content` with the representation-specific evidence (R0: the raw events in scope; R1: the relevant window
   aggregates; R2: the relevant summaries/graph neighbourhood). Compute `telemetry.evidence_bytes` as the exact UTF-8
   byte length of `content`. Leave `token_estimate`/`tokenizer` to F008's shared helper (call it if present; otherwise
   record `evidence_bytes` and a placeholder the F008 task will fill — but do not invent a tokenizer here).
4. Guarantee determinism: the same request returns a byte-identical response (stable ordering, no timestamps in the
   payload). Guarantee read-only: answering a probe does not write under the evidence or representation roots.
5. Provenance-blind: no principal in request handling, `content`, `answer`, or any surfaced summary.

## Negative test (required)

Feed a request with an unknown `probe_id`; assert the interface rejects it with a non-zero exit and a stated reason
(does not silently return an empty answer). Then feed a valid probe and confirm normal operation resumes.

## Review bundle

Standard five, plus the 18 captured probe responses, the per-probe `answer`-schema diff, and the read-only-check output.
