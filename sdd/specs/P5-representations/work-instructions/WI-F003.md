## Objective

Build `bin/lab-repr-r1 <incident>`, which produces a structured temporal ledger with derived per-window aggregates
(counts by action, deletion volume, file churn, and the reused mean+3sigma anomaly score per window). The load-bearing
property is reconciliation: the per-window event counts must sum **exactly** to the R0 total, with deterministic window
boundaries.

## Background

R1 is the middle representation: still complete, but organised into time windows with derived aggregates so a consumer
can reason about the shape of activity without reading every event. Reuse the P2 derived analytics (C5) for the
per-window density/volume/churn/anomaly figures rather than recomputing them differently — R1 must agree with the
analytics the Arm A ranker used. Window boundaries are a deterministic function of the ledger (e.g. fixed-width time or
LSN windows declared in `etc/lab.env`); record the windowing parameters. Materialise under `var/repr/<incident>/R1/`.

## Steps

1. Confirm R0 exists and is admissible (read `var/repr/<incident>/R0/manifest.json`). R1 reconciles against R0.
2. Compute per-window aggregates from the same provenance-blind events: `event_count`, per-action counts,
   `delete_count`, `file_churn`, `anomaly_score` (reuse the P2 C5 analytics; do not invent a different score). Window
   boundaries deterministic; record the windowing parameter (width, origin) used.
3. Write `var/repr/<incident>/R1/windows.jsonl` (0444), one record per window with `window_index`, `first_lsn_int`,
   `last_lsn_int`, and the aggregates. Order windows by `window_index` (integer LSN order). Compute SHA-256.
4. Emit `var/repr/<incident>/R1/manifest.json`: `event_count` = sum of per-window `event_count`;
   `ledger_event_count`; `reconciles=true` iff the per-window counts sum exactly to the R0 `event_count` **and** each
   per-window `delete_count` equals the actual deletes in that window; `provenance_blind`; `built_by_model=false`;
   `content_hash`; `source_ledger_hash`.
5. Idempotence: second run byte-identical, `changed:false`.

## Acceptance tests

| ID | Tier | Command | Expected |
| --- | --- | --- | --- |
| F003-1 | M | sum per-window `event_count` vs R0 `event_count` | exactly equal (AC-P5-03) |
| F003-2 | M | for 3 sampled windows, recount deletes in R0 within the window bounds vs R1 `delete_count` | equal for each (reconciliation) |
| F003-3 | M | window ordering by integer `first_lsn_int`; a `3/9` vs `3/10` boundary pair | ordered numerically, not lexically |
| F003-4 | M | run twice; compare `content_hash`; token scan for principal | identical; `provenance_blind=true` |

## Negative test (required)

Perturb one window's `delete_count` by +1 (off-by-one) in a scratch copy and run the reconciliation check; assert it
reports `reconciles=false` and names the offending window. Revert -> `reconciles=true`.

## Review bundle

Standard five, plus `manifest.json`, the per-window-sum-vs-R0 comparison, and the three sampled-window recounts.

## Operator review checklist

- [ ] Per-window counts sum exactly to the R0 total
- [ ] Sampled per-window delete counts reconcile to R0
- [ ] Windows ordered by integer LSN; windowing parameter recorded
- [ ] Rebuild byte-identical; no principal token
- [ ] The off-by-one negative test was caught, then reverted
