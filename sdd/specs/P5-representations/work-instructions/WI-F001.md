## Objective

Freeze `representation-interface.md` (the identical query interface) and `representation-fidelity.md` (the
determinism/completeness/reconciliation/blindness properties), and record the P5 entry gate: `bin/lab-ready` exit 0,
the target SC-01 incident having passed `bin/lab-ledger-account` exactly-once, and the name of the **default
provenance-blind ledger view** every builder must build from. No representation code is written until these shapes are
fixed.

## Background

Both contracts ship in this package under `sdd/specs/P5-representations/contracts/`. F001 does not author them — it
validates them, hash-freezes them into the review bundle, and proves the entry gate holds. The load-bearing rules are
the identical-envelope rule (`representation-interface.md` R1/R2/R3) and the admissibility rule
(`representation-fidelity.md` §4: `event_count==ledger_event_count`, `reconciles`, `provenance_blind`,
`built_by_model=false`, reproducible `content_hash`).

## Steps

1. Confirm both contract files exist and are well-formed markdown with the schema tables and example JSON that parses.
   Parse each fenced `json` block with `python3 -m json.tool` and confirm success.
2. Record the SHA-256 of each contract into `logs/review/F001/contract-hashes.txt` in the prior-tranche format
   (`<sha256>  <path>`), so future gates re-verify them byte-identical.
3. Verify and record the entry gate:
   - `set -a; source etc/lab.env; set +a; bin/lab-ready; echo "lab-ready exit=$?"` -> capture exit 0.
   - Identify the reconciled SC-01 incident (from P3) and run `bin/lab-ledger-account <incident>`; capture
     `gaps=0, duplicates=0` and exit 0.
   - Identify the **default provenance-blind view** the ledger query layer exposes (the principal-free view used by
     Arm A in P3). Confirm it does not expose `principal`/`usename`/`session_user`/UID (inspect its column list).
   - Write all facts into `logs/review/F001/entry-gate.json`
     (`{"lab_ready_exit":0,"reconciled_incident":"<id>","gaps":0,"duplicates":0,"blind_view":"<name>","blind_view_has_principal":false}`).
4. Confirm the contracts do not contradict the FROZEN `results-row.md` and `arm-coordinate.md`: the interface
   `telemetry.evidence_bytes`/`token_estimate` map onto results-row `evidence_bytes`/`token_count`, and the
   representation levels `R0`/`R1`/`R2` are exactly the `arm-coordinate.representation` values. Record the mapping in
   `logs/review/F001/contract-alignment.md`.

## Negative test (required)

Copy `representation-fidelity.md` to a scratch file and change §4 so a representation with `built_by_model=true` is
admissible; run a validator that asserts the frozen file still requires `built_by_model=false`. Assert the validator
flags the scratch mutation, and that the real file's hash is unchanged. Revert (delete scratch) -> clean.
