## Objective

Finalise the interface telemetry: exact `evidence_bytes` (UTF-8 byte length of `content`) and a `token_estimate` from a
**single vendored, pinned tokenizer** (name+version recorded), both deterministic. Prove that for the recovery-relevant
probes (`PB-4-earliest-anomaly`, `PB-6-candidate-windows`) R2 presents **strictly fewer** `evidence_bytes` and tokens
than R0 for the same probe and incident — the contribution measurement — and wire these values to the results row's
`evidence_bytes`/`token_count` fields.

## Background

The experiment measures the evidence a modest model must read to find the recovery point. `evidence_bytes` is the exact,
model-independent primary measure (ADR-P5-5). `token_estimate` is a declared estimate from one pinned tokenizer so it
is deterministic and comparable across arms; it is **not** the real tokens the P6 model consumes (that is captured in
P6). Vendor the tokenizer as a pinned file under `vendor/tokenizer/`; record its name+version; never call a model.

## Steps

1. Vendor one tokenizer as a pinned local file under `vendor/tokenizer/` (a byte-level BPE table or equivalent that
   runs offline in pure Python). Record `tokenizer` name+version in `etc/lab.env`. No network, no model.
2. Add a shared helper the interface calls so every response's `telemetry.token_estimate` is produced by that one
   tokenizer, and `telemetry.tokenizer` names it. `evidence_bytes` = exact `len(content.encode('utf-8'))`.
3. Run all 6 probes x 3 representations; record a telemetry table
   (`logs/review/F008/telemetry.json`: `{probe_id, representation, evidence_bytes, token_estimate}`).
4. Assert determinism: re-run the sweep; telemetry byte-identical.
5. Assert the contribution delta: for `PB-4` and `PB-6`, `R2.evidence_bytes < R0.evidence_bytes` and
   `R2.token_estimate < R0.token_estimate` for the SC-01 incident. Record the deltas.
6. Demonstrate the results-row wiring: show that when an arm coordinate is scored (P1 `evaluate-arm`), the
   `evidence_bytes`/`token_count` fields are populated from this telemetry for the queried representation. (Do not
   modify the frozen results-row schema; only show the values flow into the existing fields.)

## Negative test (required)

Swap in a second, different tokenizer in a scratch run and assert the recorded `telemetry.tokenizer` no longer matches
the declared pinned name, so the determinism/declared-tokenizer check fails. Revert to the pinned tokenizer -> passes.
(This proves the telemetry is tied to one declared tokenizer, not whatever happens to be importable.)
