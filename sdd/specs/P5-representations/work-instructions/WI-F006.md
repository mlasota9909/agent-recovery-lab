## Objective

Prove, mechanically, that all three representations are **admissible** per `representation-fidelity.md` §4: each
rebuilds byte-identical (determinism), R1 aggregates and R2 summaries reconcile exactly to R0/ledger counts (fidelity —
no omission, no fabrication), no principal token appears anywhere (provenance-blindness), and all three share the one
reconciled SC-01 `incident_id` (incident-scoped). Build `bin/lab-repr-admit <incident>` that runs these checks and
prints an admissibility verdict per representation.

## Background

This is the honesty gate for the contribution. A representation that fails any of these must not be fed to a model in
P6. The checks re-derive everything from the artefacts and the ledger; they never trust the manifest's own boolean
without recomputing it.

## Steps

1. **Determinism:** rebuild each representation into a scratch location and compare its `content_hash` (and the raw
   artefact bytes) to the committed one. Assert byte-identical for R0, R1, R2.
2. **Completeness:** assert `event_count == ledger_event_count` for R0; assert R1 per-window counts sum to the R0
   total; assert R2's represented event count equals R0's.
3. **Reconciliation:** independently recompute a sample of R1 aggregates and R2 summary figures from R0 events and
   assert equality; recompute the full deletion-per-window vector and assert R1 and the R2 summaries both match it.
4. **Blindness:** run a structured scan (known field names) and a token scan (regex for the principal identifiers and
   the known role names `lab_app`/`lab_agent`) across every R0/R1/R2 artefact, summary, node/edge label and a full
   probe sweep of `bin/lab-repr-query`; assert zero hits.
5. **Incident-scope:** assert all three manifests carry the same `incident_id`, equal to the reconciled SC-01 incident.
6. Emit `logs/review/F006/admissibility.json` with a per-representation verdict object
   (`{representation, deterministic, complete, reconciles, provenance_blind, incident_id, admissible}`).

## Negative test (required)

Three parts, run independently and reverted:
(a) In a scratch R1, drop one window (omission); assert completeness fails (`event_count`!=ledger).
(b) In a scratch R2, corrupt one summary figure; assert reconciliation fails.
(c) In a scratch R0, inject a `lab_agent` principal token into one record; assert the blindness scan flags it.
Each must be caught; revert all -> all admissible again.

## Review bundle

Standard five, plus `admissibility.json`, `reconciliation.md`, and the three negative-case outputs.

## Operator review checklist

- [ ] Zero principal tokens across artefacts, summaries and a full probe sweep
- [ ] All three share the reconciled SC-01 incident_id
- [ ] All three negative cases (omission, fabrication, principal leak) were caught, then reverted
