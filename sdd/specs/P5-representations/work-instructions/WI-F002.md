## Objective

Build `bin/lab-repr-r0 <incident>`, which serializes every provenance-blind ledger event for the incident into a
canonical, strictly integer-LSN-ordered flat log, and emits a fidelity manifest. R0 is the naive representation and the
base every other representation reconciles against, so its completeness is load-bearing: its `event_count` must equal
the ledger event count for the incident **exactly**.

## Background

R0 is the whole change stream, in order, with nothing derived. Build it from the default provenance-blind view recorded
in F001 (never a principal-exposing view). The canonical form must be deterministic: fixed field order, fixed
serialization, strict ordering by integer `lsn_int` then a stable tiebreak (e.g. `(xid, table, action, natural_key)`
from the frozen ledger key), no build timestamp embedded in the artefact. Materialise under
`var/repr/<incident>/R0/`.

## Steps

1. Read the reconciled ledger for `<incident>` via the F001 blind view. Confirm reconciliation first
   (`bin/lab-ledger-account <incident>` gaps=0/dups=0); refuse if not reconciled.
2. Serialize each event as a canonical line/record with a fixed field order: `lsn_int`, `lsn_text`, `wall_clock`,
   `action`, `object` (relation or file path), `natural_key`, and the change detail — **excluding any principal
   field**. Order strictly by integer `lsn_int`, tiebreak by the frozen ledger key. No string LSN comparison.
3. Write the canonical artefact to `var/repr/<incident>/R0/events.jsonl` (0444) and compute its SHA-256.
4. Emit the fidelity manifest `var/repr/<incident>/R0/manifest.json` per `representation-fidelity.md` §3:
   `event_count` = serialized events; `ledger_event_count` = events in the source ledger for the incident;
   `reconciles=true` iff they are equal (R0 has no aggregates to reconcile beyond the count); `provenance_blind` from a
   token scan of the artefact; `built_by_model=false`; `content_hash` = the artefact SHA-256; `source_ledger_hash`.
5. Idempotence: a second run detects the existing artefact with the same `content_hash` and reports `changed:false`.

## Acceptance tests

| ID | Tier | Command | Expected |
| --- | --- | --- | --- |
| F002-1 | M | count records in `events.jsonl` vs ledger event count for the incident | equal (`event_count==ledger_event_count`) (AC-P5-02) |
| F002-2 | M | check ordering: `lsn_int` is non-decreasing across the file, integer comparison | strictly ordered; a `3/9` vs `3/10` pair (if present) ordered numerically |
| F002-3 | M | token scan of `events.jsonl` for principal/usename/session_user/UID | none found; `provenance_blind=true` |
| F002-4 | M | run `bin/lab-repr-r0` twice; compare `content_hash` | identical; second run `changed:false` |

## Negative test (required)

Point the builder at a view that includes the principal column (or inject a synthetic principal field into one source
row) and run; assert the token scan flags it and the manifest reports `provenance_blind=false` (so the artefact is
inadmissible). Revert to the blind view -> `provenance_blind=true`.

## Review bundle

Standard five, plus a copy of `manifest.json`, the two `content_hash` values from the idempotence run, and the
event-count comparison.

## Operator review checklist

- [ ] R0 event count equals the ledger event count exactly
- [ ] Events strictly ordered by integer LSN
- [ ] No principal token anywhere in the artefact
- [ ] Rebuild is byte-identical (`content_hash` stable)
- [ ] The negative test caught an injected principal, then reverted
