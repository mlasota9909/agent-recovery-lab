## Objective

Make the acceptance suite report what it actually verified. Delete the prose-matching helper, give every criterion a
tier, print per-tier totals, and re-implement the two load-bearing attested criteria as live mechanical checks.

## The defect, precisely

`bin/lab-verify` resolves nine of eighteen criteria through a helper equivalent to:

```
return token in text and "FAIL" not in text
```

where `text` is a markdown file written by the agent that implemented the criterion. Consequences:

- **It conflates two different things** under one "18/18 PASS" headline: nine criteria mechanically verified against
  live state, and nine criteria verified by finding a word in the implementer's own narrative.
- **It is brittle in an absurd direction.** An honest observation containing the word FAIL — for example "the pre-repair
  behaviour was FAIL" — flips a criterion red. So the helper simultaneously accepts too much and rejects too much.
- **Two of the nine are load-bearing.** AC-6 (before-images) and AC-14 (heartbeat density) support measurements the
  experiment depends on, and a regression in either would not surface until P5.

This is not fraud and most of the underlying work was genuinely done. The fix is honesty plus targeted upgrade, not a
wholesale re-derivation.

## Tier definitions (Article XIII)

- **Tier M, mechanical.** Re-derived at verification time from live system state or from a committed
  machine-readable artefact. Passes or fails on its own evidence with no reference to any narrative.
- **Tier A, attested.** A recorded observation of a one-time event not cheaply re-derivable. Must still assert on a
  **machine-readable field** — a `lab.env` key, a JSON field, a captured exit code. Never a token in prose.

## Steps

1. Enumerate all eighteen P0 criteria and assign a tier to each. Record the assignment and the justification in
   `docs/acceptance-tiers.md`. Expect roughly nine already-mechanical to stay M, two to be upgraded to M, and seven to
   remain A.
2. **Delete the prose-matching helper** from `bin/lab-verify` entirely. Not deprecated, not bypassed — removed. Any
   criterion still depending on it must be re-pointed at a machine-readable field first.
3. For each remaining tier A criterion, re-point it at a machine-readable assertion. Examples of acceptable targets: a
   key and expected value in `etc/lab.env`; a named field in a committed JSON artefact from the original task's review
   bundle; a recorded exit code in `commands.log`. If a criterion has no machine-readable target, create one by
   emitting a small JSON artefact from the original evidence rather than by parsing prose.
4. **Re-implement AC-6 as tier M.** At verification time, against the live cluster: `UPDATE` and then `DELETE` a row
   in a scenario relation, read the decoded stream, and assert the change records carry the **old tuple values**, not
   merely the key. Assert positively on a specific column value, not on the presence of a field name. Clean up the
   test row.
5. **Re-implement AC-14 as tier M.** At verification time: sample a window of `lab_heartbeat` rows, assert the
   inter-row interval is within tolerance of 1 s across the window, and assert the recorded LSNs are strictly
   monotonic using integer arithmetic — reuse the existing `(high << 32) + low` conversion from `bin/lab-coordinate`;
   do not compare LSN strings lexically.
6. Change the summary output. It MUST print per-tier totals, for example
   `TIER M: 11/11 PASS · TIER A: 7/7 PASS · TOTAL: 18/18`. A single undifferentiated headline is prohibited. If any
   criterion fails, the suite exits non-zero as before.
7. Add `bin/lab-verify --json`, emitting `{"criteria":[{id, tier, requirement, command, expected, observed, result}],
   "totals":{...}}`. This becomes the machine-readable acceptance artefact.
8. Do not change any criterion's substance — only how it is verified and reported. If you believe a criterion is wrong,
   record it in `observations.md` and leave it.

## Negative test (required)

Three, each proving a specific check can fail.

**N-1, AC-6 can fail.** Set `REPLICA IDENTITY DEFAULT` on one scenario relation, re-run AC-6, and confirm it fails
because the decoded `DELETE` now carries only the key. Restore `FULL`, re-run, confirm pass. Capture both decoded
records side by side — this is the same artefact that made T014 valuable, and it belongs in the recorded evidence.

**N-2, AC-14 can fail.** Stop the heartbeat writer for longer than the tolerance window, re-run AC-14, confirm
failure on the interval assertion. Restart, confirm pass.

**N-3, the prose matcher is genuinely gone.** Take a tier A criterion, corrupt the machine-readable field it now
asserts on, and confirm the criterion fails. Restore. This proves tier A criteria assert on data, not narrative.

## Non-regression (required)

- Every criterion that passed before this task still passes, with the same substance. Produce a before/after table of
  all eighteen results.
- R002's enumeration and regression criteria are represented in the suite and pass.
- R003's consumer-liveness and slot-fails-closed conditions are represented in the suite and pass.
- The suite still exits non-zero when any criterion fails — demonstrate with one of the negative tests above.
