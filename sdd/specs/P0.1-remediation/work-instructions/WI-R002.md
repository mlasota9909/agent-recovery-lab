## Objective

Make the out-of-band isolation claim true of the code as written. Delete every test-only widening path from the WAL
append channel, re-implement the isolation suite's red phase by mutating state outside the component under test, and
add a command-surface enumeration test so the defect cannot silently return.

## The defect, precisely

`bin/lab-wal-receive` is the forced SSH command for the guest `postgres` principal. It is the entire outward channel
from victim to host, and therefore the whole of the isolation claim. It currently contains a branch equivalent to:

```
if [[ ${SSH_ORIGINAL_COMMAND:-} == "t009-read-evidence-probe" &&
      -f "$SCRIPT_DIR/.t009-regression-read-enabled" ]]; then
  cat "$EVIDENCE_ROOT/.lab-isolation-probe"
```

The sentinel is host-owned and currently absent, so the path is shut. That is not sufficient. Constitution Article XII
prohibits the class regardless of default state, for three reasons set out in `spec.md` §2 F-1: no criterion asserts
the sentinel's absence, the mechanism makes AC-13 circular, and anyone who reads this file will not accept
the isolation claim.

## Steps

### Part 1 — remove

1. Copy `bin/lab-wal-receive` to your review bundle as `lab-wal-receive.before` for the diff record.
2. Delete **both** `t009-*` branches entirely. Do not comment them out, do not guard them harder, do not move them
   behind a root check, do not replace them with an environment variable. Delete.
3. Search the whole deploy root for the sentinel and any sibling: `.t009-regression-read-enabled`,
   `.lab-isolation-probe`, and any file matching `.t009-*`. Remove them. Record what existed before removal.
4. Re-read the file start to finish and confirm the only filesystem write it performs is the append to the current
   incident's archive directory, and the only read it performs is whatever it needs to detect an existing segment for
   overwrite refusal. Any other read or write is a finding — record it and stop.

### Part 2 — regression by external mutation

5. Rewrite the `--regression` phase of `bin/lab-isolation-test` to use **ADR-P01-2 mechanism 1** (preferred):
   - create a scratch file under `EVIDENCE_ROOT`, host-side;
   - chown/chmod it so the victim principal can genuinely read it through its existing legitimate access, thereby
     creating a real violation of FR-1.1's spirit that the suite must detect;
   - re-run the suite and **require FAIL**;
   - restore ownership and mode;
   - re-run and **require PASS**;
   - emit all three phases as JSON.
6. If mechanism 1 cannot produce a genuine red — because the victim has no path by which to reach even a
   world-readable file under `EVIDENCE_ROOT`, which is the desired state — fall back to **mechanism 2**: add a
   temporary authorised-key entry for the guest principal *without* `command=`, so an unrestricted channel genuinely
   exists; require FAIL; then remove the entry, destroy the keypair, and assert both. Record which mechanism you used
   and why.
7. If `--regression` does not observe a FAIL in its middle phase, exit non-zero. A regression harness that cannot go
   red is worthless (Article VIII).
8. Preserve the existing permission-denied versus file-not-found distinction. A `not found` result is an ERROR, never
   a PASS. This is the most common way an isolation suite silently lies.

### Part 3 — enumeration corpus

9. Add `bin/lab-isolation-test --enumerate`, which presents a fixed corpus of candidate `SSH_ORIGINAL_COMMAND` values
   to the channel as the guest `postgres` principal and asserts the outcome of each. The corpus MUST include at least
   these twelve cases:

| # | Candidate command | Expected |
| --- | --- | --- |
| 1 | `t009-read-evidence-probe` (the removed probe) | refused, non-zero |
| 2 | `append <new-segment>` | succeeds |
| 3 | `append <segment-that-already-exists>` | refused as overwrite |
| 4 | `append ../../../etc/passwd` | refused |
| 5 | `append /etc/passwd` | refused |
| 6 | `append` (no argument) | refused |
| 7 | `read <path>` | refused |
| 8 | `cat <path>` | refused |
| 9 | `list` | refused |
| 10 | `` (empty) | refused |
| 11 | `append x; cat /etc/passwd` | refused |
| 12 | `append x$(printf '\n')cat /etc/passwd` | refused |

10. Emit the corpus results as JSON: one object per candidate with the command, expected, observed, exit code and
    result. Exit non-zero if any candidate deviates from expectation.
11. Record the corpus and its results as the evidence for the isolation claim. This artefact replaces the
    previous AC-13 evidence.

## Negative test (required)

Two, both mandatory.

**N-1, the hatch cannot return undetected.** Temporarily re-add a trivial magic branch to `bin/lab-wal-receive` — a
command string that exits 0 without appending. Run `--enumerate` and confirm it goes red because that string is not in
the accepted class. Remove the branch, re-run, confirm green. This proves the enumeration test is the durable fix, not
decoration.

**N-2, the regression harness genuinely detects violation.** Already covered by `--regression`, but capture its full
three-phase output. If the middle phase passes, the harness is broken and the task fails.

## Non-regression (required)

Before finishing, re-prove the pre-existing legitimate behaviour:

- WAL archiving from the guest still succeeds end to end (produce a segment, confirm it lands in the current
  incident's archive directory with the expected mode).
- Overwrite refusal still works, and the original segment's bytes are unchanged after a refused attempt.
- `bin/lab-verify` still passes its archive-related criteria (whatever their current tier — R004 re-tiers them).

Record all three in `non-regression.md`. A repair that breaks the append path is a failure, not a trade-off.

`mechanism.md` recording which ADR-P01-2 mechanism was used and why.
