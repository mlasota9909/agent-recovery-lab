## Objective

Build `bin/lab-arm-b-prompt`: the **one and only** path that assembles model input. It obtains the six-key `model_view`
from `bin/lab-repr-modelview`, passes it through `bin/lab-modelview-guard`, and renders the fixed prompt template
(`arm-b-protocol` §2, R1) around `model_view.content`. Prove the assembled prompt is identical across R0/R1/R2 except
the injected `content`, and prove no other code path builds or sends model input.

## Background

This is the integrity keystone and the direct answer to the P5.1-review carry-forward: the guard's value is realised
only if every model-input path routes through it. The prompt template — system prompt, task, answer-format
instructions (the `COORDINATE:`/`REFUSAL:` grammar), refusal permission — is byte-identical across representations;
only `model_view.content` differs. The guard rejects any `model_view` carrying an `answer`/`reference` key, a
coordinate field, or a provenance token before templating.

## Steps

1. `bin/lab-arm-b-prompt --incident <id> --representation <R0|R1|R2>`: call `bin/lab-repr-modelview` for the fixed probe
   `PB-6-candidate-windows`; pipe the returned `model_view` through `bin/lab-modelview-guard`; on guard failure, exit
   non-zero and do not template (fail loud).
2. Render the fixed prompt template from `arm-b-protocol` around `model_view.content`. The template text is a constant
   in the script (or a pinned template file); only `content` is interpolated. Emit the assembled prompt to stdout / the
   `--out` file.
3. **Parity proof.** Assemble the prompt for R0, R1, R2 (same incident, same probe); diff them; assert they differ only
   within the interpolated `content` region and are byte-identical elsewhere (system prompt, task, format instructions).
4. **Single-choke-point proof.** Scan the repository (`bin/`, `lib/`) for any other code that constructs a model prompt
   or calls `bin/lab-model` directly without going through `bin/lab-arm-b-prompt`. Record the scan and assert the only
   caller of `bin/lab-model` for Arm B is the driver `bin/lab-arm-b` via this assembler. Emit
   `logs/review/H003/chokepoint-scan.json` (`{"prompt_assemblers":["bin/lab-arm-b-prompt"],"lab_model_callers":[...],"bypass_found":false}`).
5. Confirm the guard is actually invoked: a `model_view` with an injected `answer` key is refused here before any
   template/model call.

## Negative test (required)

Add a scratch second script that builds a prompt from `model_view.content` and calls `bin/lab-model` directly, bypassing
the guard. Re-run the single-choke-point scan and assert it reports `bypass_found=true` and fails. Remove the scratch
script -> scan reports `bypass_found=false` and passes. (This proves the choke-point scan actually detects a bypass.)

## Review bundle

Standard five, plus `prompt-parity.md`, `chokepoint-scan.json`, and the guard-refusal outputs.

## Operator review checklist

- [ ] The guard is called before templating; an injected `answer` or provenance token is refused
- [ ] The scan shows exactly one prompt-assembly path and no bypass of the guard
- [ ] The negative test caught an added bypass path, then reverted
