## Objective

Build `bin/lab-arm-b`: the driver that, for a given representation, assembles the guarded prompt (H003), invokes the
offline model (H002), extracts the outcome (H004), and records each of K replicates as a determination or a refusal
with the raw completion retained. It never re-prompts to coerce an answer and never substitutes a guess for a refusal.

## Background

This composes the three Phase-B/C components into one repeatable run. The replicate count K (default 5, from
`arm-b-protocol` R8) characterises the model's residual non-determinism under the pinned decoding. All K completions are
retained verbatim; the per-representation outcome and the replicate agreement (identical-coordinate rate) are computed
from the K records. Scoring and telemetry are wired in H006–H008; H005 owns the run loop and the refusal handling.

## Steps

1. `bin/lab-arm-b --incident <id> --representation <R0|R1|R2> [--replicates K]`: for `r in 0..K-1`, assemble the guarded
   prompt, call `bin/lab-model` (new invocation each replicate — never reuse a cached completion), extract via
   `bin/lab-arm-b-extract`, and write one replicate record per `arm-b-protocol` §4 (`outcome`, `arm_coordinate` or null,
   `raw_completion_sha256`, `prompt_tokens`, `completion_tokens`, `latency_ms`; `score`/`coordinate_error` filled later).
2. Retain each raw completion verbatim under `var/arm_b/<incident>/<representation>/replicate-<r>.completion`.
3. **Refusal handling.** A refusal replicate is recorded as-is (`outcome="refusal"`). The driver does not re-prompt,
   does not lower the bar, does not fill a coordinate. Record the refusal count per representation.
4. **Replicate agreement.** Compute the identical-coordinate rate across the K determinations (how often the same
   `lsn_int` is chosen) and the refusal rate; write `var/arm_b/<incident>/<representation>/replicates.json`.
5. Idempotence: re-running appends a new *batch* under a timestamped run id or refuses to overwrite an existing batch;
   it never mutates a retained completion.

## Acceptance tests

| ID | Tier | Command | Expected |

| H005-1 | M | run `bin/lab-arm-b` for one representation with K=5 | 5 replicate records, 5 verbatim completions retained, each an outcome (determination/refusal) |

| H005-3 | M | force the model to emit a `REFUSAL:` line (fixed prompt fixture) and run | recorded as refusal; no coordinate; no re-prompt (AC-P6-07 behaviour) |
| H005-4 | M | re-run the driver | appends a new batch or refuses to overwrite; no retained completion mutated |

## Negative test (required)

Add a scratch flag to the driver that, on a refusal, re-prompts the model up to 3 times "until it answers". Assert a
check detects the coercion (more than one model call recorded for a single replicate, or a refusal converted to a
determination on retry) and fails. Remove the flag -> one call per replicate, refusals preserved.

## Review bundle

Standard five, plus `replicates.json` and the retained completions for one representation.

## Operator review checklist

- [ ] K replicates are run, each with a fresh model call, all completions retained verbatim
- [ ] Refusals are recorded as-is; the driver never re-prompts or coerces
- [ ] Replicate agreement and refusal rate are computed from the K records
- [ ] The negative test caught a coercive re-prompt loop, then reverted
