## Objective

Record the **real**, model-specific `prompt_tokens` and `latency_ms` for each run and land them in the results row's
telemetry, stored **distinct** from P5's pinned-tokenizer `token_estimate` for the same probe/representation. This
closes ADR-P5-5: P5 gave a model-independent estimate; P6 gives the actual model consumption.

## Background

P5's telemetry recorded `evidence_bytes` (exact, model-independent) and a `token_estimate` from a vendored pinned
tokenizer, explicitly deferring the real token count to P6. H007 captures the runtime-reported `prompt_tokens` (what
the model actually ingested for the representation's `content`) and pairs it with the P5 estimate so the results can show
both: the estimate for cross-model comparability, the real count for this model.

## Steps

1. For each replicate, read `prompt_tokens`/`completion_tokens`/`latency_ms` from the `bin/lab-model` record.
2. Land `prompt_tokens` into the results row `token_count` (real) for the Arm B run, and carry the P5
   `token_estimate` for the same probe/representation alongside as `token_estimate` so both are visible; record
   `evidence_bytes` from the P5 `model_view.content` byte length (the bytes actually shown to the model).
3. Emit `logs/review/H007/telemetry.json` per representation:
   `{representation, evidence_bytes, token_estimate_p5, prompt_tokens_real, latency_ms_median}` across the K replicates.
4. Assert the real `prompt_tokens` is recorded as a **separate field** from the P5 estimate (they are not conflated),
   and note the ratio real/estimate for the record.

## Negative test (required)

In a scratch wiring, write the P5 `token_estimate` into the `prompt_tokens_real` field (conflating estimate and real).
Assert a check that compares the field's provenance (must originate from the `bin/lab-model` runtime record, not the
P5 tokenizer) catches the conflation and fails. Revert -> the real count originates from the runtime record.
