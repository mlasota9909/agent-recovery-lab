## Objective

Capture the model's operator-facing explanation verbatim into the results directory and wire it to the
`arm-coordinate.rationale` field, asserting it carries no provenance token (Article II). These explanations are strong
qualitative evidence and directly support the operator-assistance argument.

## Background

`arm-coordinate` R6 requires the rationale to be the model's own words (verbatim, as qualitative evidence), provenance-scrubbed
only for the blindness assertion — never paraphrased or invented. The rationale is the model's reasoning text
preceding the final tagged line; H006 extracts and stores it and checks blindness.

## Steps

1. For each determination replicate, take the completion text preceding the final `COORDINATE:` line as the rationale
   (verbatim). For a refusal, the `REFUSAL:` reason text is the rationale.
2. Store rationales verbatim under `var/arm_b/<incident>/<rep>/replicate-<r>.rationale.txt` and set the
   `arm_coordinate.rationale` field to the verbatim text (determinations only).
3. **Blindness scan.** Assert no `principal`/`usename`/`session_user`/UID token appears in any rationale (structured
   check + token scan). Because the model only ever saw the provenance-blind `model_view`, a leak here would indicate a
   guard or representation defect — record the scan result either way.
4. Emit `logs/review/H006/rationale-blindness.json` (`{"rationales":N,"provenance_tokens_found":0}`) and copy two
   sample rationales into the bundle as qualitative evidence.

## Negative test (required)

Inject a synthetic rationale containing `usename=lab_agent` into a scratch replicate and run the blindness scan; assert
`provenance_tokens_found>0` and the check fails. Remove the injected rationale -> scan clean.

## Review bundle

Standard five, plus `rationale-blindness.json`, `sample-rationales.md`.
