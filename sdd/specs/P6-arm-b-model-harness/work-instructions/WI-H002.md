## Objective

Build `bin/lab-model`: the single wrapper that invokes the pinned offline model over its loopback endpoint with greedy
decoding and the fixed seed, captures the exact bytes sent and the exact completion returned, records the runtime's
real `prompt_tokens`/`completion_tokens` and the wall-clock `latency_ms`, and **verifies no outbound socket was opened**
during the call (Article X). This is the only component that talks to the model.

## Background

Everything the model ever sees flows through `bin/lab-model`, and it accepts only an already-assembled prompt on stdin
(the assembly and guarding happen in H003). `bin/lab-model` must not read the ledger, the reference answer, the
injection log or the oracle (model-runtime R6). The offline proof is load-bearing: the whole containment argument
(Article X) depends on the model making no outbound call.

## Steps

1. Read `var/model/model-runtime.json` and `etc/lab.env` for the endpoint, decoding params and weights hash. Refuse to
   run if `endpoint` is not a loopback address, if `temperature!=0`, or if `weights_sha256` is unset/placeholder.
2. `bin/lab-model` reads the assembled prompt from stdin (or `--prompt-file`), sends it to the loopback endpoint with
   the pinned decoding, and captures: the verbatim prompt, the verbatim completion, `prompt_tokens`,
   `completion_tokens`, `latency_ms`, plus the echoed `model_id`/`weights_sha256`/`seed`. Writes one JSON record to the
   path given by `--out`.
3. **Offline proof.** Wrap the invocation so outbound connections are observed: capture the process's socket activity
   for the duration (e.g. count non-loopback outbound connections). Record `outbound_connections` (must be 0) and set
   `offline_verified=true` only when 0. If any non-loopback connection is observed, exit non-zero and mark the run a
   containment violation.
4. Confirm at load time that the weights file on disk hashes to the recorded `weights_sha256`; refuse if it drifted
   (the model silently changed).
5. Idempotence/determinism note: `bin/lab-model` appends a new invocation record; it never overwrites a prior recorded
   completion. Given the runtime's greedy+seed pinning, record whether the runtime is byte-reproducible (some runtimes
   are not fully deterministic even at temp 0 — record the observed reproducibility rather than asserting it).

## Acceptance tests

| ID | Tier | Command | Expected |
| --- | --- | --- | --- |
| H002-1 | M | invoke `bin/lab-model` on a trivial fixed prompt; inspect the record | records verbatim prompt+completion, real `prompt_tokens`/`completion_tokens`/`latency_ms`, echoed `weights_sha256`/`seed` (AC-P6-02) |
| H002-2 | M | inspect `outbound_connections` and `offline_verified` in the record | `outbound_connections==0`, `offline_verified==true` (AC-P6-02, Article X) |
| H002-3 | M | point `endpoint` at a non-loopback address (scratch env) and run | refuses with non-zero exit (loopback-only enforced) |
| H002-4 | M | corrupt the recorded `weights_sha256` (scratch) and run | refuses: weights-hash drift detected |

## Negative test (required)

In a scratch wrapper, make `bin/lab-model` open a real non-loopback outbound connection (e.g. to a loopback-forwarded
port that egresses) during the call, and assert the offline check reports `outbound_connections>0` and the run is
rejected as a containment violation. Revert -> `outbound_connections==0`, run accepted.

## Review bundle

Standard five, plus `sample-invocation.json` and the offline-check evidence (the socket observation output).

## Operator review checklist

- [ ] `bin/lab-model` invokes only the loopback endpoint with greedy+seed
- [ ] Verbatim prompt and completion, real token counts and latency are captured
- [ ] The per-invocation offline proof shows zero outbound connections
- [ ] Weights-hash drift and non-loopback endpoints are both refused
- [ ] The negative test caught a real outbound connection, then reverted
