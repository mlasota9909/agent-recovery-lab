## Objective

Produce the tranche's headline on the reconciled SC-01 incident: run the same pinned model over R0, R1 and R2 (K
replicates each) through the guarded interface, compute the **objective coordinate error vs ground truth** for each
determination and append every run automatically to the results file, and present the R0-vs-R1-vs-R2 comparison.
Then prove the three discrimination negatives — a bypassed guard changes the outcome and is caught, a coerced refusal
is caught, and an injected principal is caught — so guard, refusal and blindness are shown enforced, not assumed.

## Background

This is why P6 exists. The comparison holds the model constant and varies only the representation. Ground truth is the
known optimal recovery coordinate for the scripted SC-01 incident (the latest safe point before the malicious burst,
established by P3/P4). "Objective error" = the integer-LSN delta between the model's chosen coordinate and the optimum,
plus the P4-scored `damage_rows_retained`/`legit_rows_lost`. The expectation the research hypothesis predicts: R2 (summaries) lets
the modest model locate the point on far less evidence than R0 (raw log), with fewer refusals and lower error. If that
is **not** what happens, report it honestly — a null or inverted result is a finding, not a failure to hide.

## Steps

1. Run `bin/lab-arm-b` for R0, R1, R2 (K replicates each) on the SC-01 incident. Each determination is scored (H008),
   telemetry captured (H007), rationale captured (H006).
2. Compute per-run objective error vs ground truth: `lsn_delta = |chosen_lsn_int - optimum_lsn_int|` (integer), plus
   `damage_rows_retained`, `legit_rows_lost`, and `coord_direction` (before/after the optimum). Refusals are counted as
   refusals (no error value), not as zero error and not as max error — reported separately.
3. **Append automatically.** Every run (determination and refusal) is appended to the results file by the driver, one
   row per replicate, with no manual step (the roadmap's acceptance test). Confirm the row count equals `3 * K`.
4. Emit `logs/review/H009/headline.json`:
   `{true_optimum:{lsn_int,window}, per_rep:{R0,R1,R2}:{determinations,refusals,median_lsn_delta,median_damage_retained,median_legit_lost,identical_coord_rate,evidence_bytes,prompt_tokens_real}}, r0_vs_r2}` and a `headline.md`
   results table. All values sourced from committed fields, never prose.
5. **Discrimination negatives:**
   - (a) **Guard bypass:** assemble the model input with the `reference` answer deliberately included (bypassing the
     guard), run once, and show the outcome changes (the model can now read the coordinate) AND the guard/choke-point
     check flags the bypass. Then restore the guard.
   - (b) **Coerced refusal:** feed a refusal-worthy completion through the coerced-guess path (H004 negative machinery)
     and show it is caught (a coordinate must not appear).
   - (c) **Injected principal:** inject a provenance token into the model input and show the guard refuses it.
6. Record the honest interpretation: state the observed R0-vs-R1-vs-R2 ordering and whether it matches the hypothesised
   ordering; if R0 exceeds the model's context window and forces truncation/refusal, report that as a finding.

## Negative test (required)

Construct a scratch R2 headline where the model's chosen coordinate is scored against a **wrong** optimum (a coordinate
known to retain damage) yet reported as zero error; assert the error computation, re-derived from the true optimum and
the committed coordinate, catches the mismatch and fails. Revert -> error computed against the true optimum.
