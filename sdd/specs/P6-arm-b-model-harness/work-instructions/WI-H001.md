## Objective

Freeze `model-runtime.md` (the offline-model pinning) and `arm-b-protocol.md` (the fixed prompt/query/extraction/refusal
protocol); **discover and record** the model id, quantisation and weights SHA-256 of the offline model actually
installed; and record the P6 entry gate: `bin/lab-regression` green, the SC-01 representations R0/R1/R2 admissible, and
the model runtime healthy and provably offline. No invocation code is written until these are fixed.

## Background

Both contracts ship in this package under `sdd/specs/P6-arm-b-model-harness/contracts/`. H001 does not author them — it
validates them, fills the model-runtime record with **discovered** values (never guessed), hash-freezes both into the
review bundle, and proves the entry gate. `bin/lab-ready` exiting 1 is expected (frozen headline, ADR-P6-7) and is NOT
a blocker; use `bin/lab-regression` instead. The load-bearing rules are model-runtime R1/R2/R4 (one pinned model,
offline, greedy+seed) and arm-b-protocol R2/R4/R5 (single guarded assembly path, deterministic extraction grammar,
refusal never coerced).

## Steps

1. Confirm both contract files exist and are well-formed markdown with schema tables and example JSON. Parse each
   fenced `json` block with `python3 -m json.tool`.
2. **Discover the model.** Inspect the installed offline runtime and model: record `model_id`, `quantization`, the
   `weights_sha256` of the loaded weights file(s), the `runtime` name+version, the loopback `endpoint`, the
   `context_window`, and the pinned `decoding` (`temperature=0, top_p=1, top_k=0, seed=<int>, max_tokens=<int>`). Write
   these into `etc/lab.env` (keys `MODEL_ID`, `MODEL_QUANT`, `MODEL_WEIGHTS_SHA256`, `MODEL_RUNTIME`, `MODEL_ENDPOINT`,
   `MODEL_SEED`, `MODEL_MAX_TOKENS`, `MODEL_CONTEXT`) and materialise `var/model/model-runtime.json` per the contract.
   Confirm `endpoint` is a loopback address (`127.0.0.1`/`::1`/`localhost`).
3. Record the SHA-256 of each contract into `logs/review/H001/contract-hashes.txt` (`<sha256>  <path>`).
4. Verify and record the entry gate:
   - `set -a; source etc/lab.env; set +a; bin/lab-regression; echo "regression exit=$?"` -> capture exit 0.
   - Note `bin/lab-ready` exit (expected 1, `lab_ready_blocked_by=frozen_headline*`); record it as expected, not a
     blocker.
   - Identify the reconciled SC-01 incident id and confirm its R0/R1/R2 representation manifests are admissible (from
     P5 F006: `event_count==ledger`, `reconciles=true`, `provenance_blind=true`, `built_by_model=false`).
   - Write `logs/review/H001/entry-gate.json`
     (`{"regression_exit":0,"lab_ready_exit":1,"lab_ready_expected":true,"sc01_incident":"<id>","repr_admissible":{"R0":true,"R1":true,"R2":true},"model_offline_endpoint":"<loopback>"}`).
5. Confirm the contracts do not contradict the FROZEN `arm-coordinate.md` and `results-row.md`: Arm B emits the
   arm-coordinate shape (`arm=arm_b`, `representation` in {R0,R1,R2}, `selection_inputs.read_*` false); real token count
   lands in results-row `token_count`. Record the mapping in `logs/review/H001/contract-alignment.md`.

## Negative test (required)

Copy `model-runtime.md` to a scratch file and change R4 so `temperature=0.7` (sampling) is admissible; run a validator
that asserts the frozen file still requires `temperature=0`. Assert the validator flags the scratch mutation, and that
the real file's hash is unchanged. Revert (delete scratch) -> clean.

`model-runtime.json`, `contract-hashes.txt`, `entry-gate.json`, `contract-alignment.md`.
