## Objective

Build `bin/lab-arm-b-extract`: parse the model's completion for the single machine-parsable final line
(`COORDINATE: window=<int> lsn=<lsn-text>` or `REFUSAL: <reason>`), resolve a determination into the frozen
arm-coordinate shape via `bin/lab-coordinate` (integer LSN), and record any ambiguity, absence, or unparsable/out-of-range
coordinate as a **refusal** — never a guess. Extraction is a deterministic pure function of the completion.

## Background

Extraction is where a stochastic completion becomes a deterministic, scoreable coordinate — or an honest refusal. The
grammar is fixed in `arm-b-protocol` R4/R5. The critical rule (Article VIII): if the model did not produce a clean
determination, the outcome is a refusal; the harness never substitutes a heuristic or "closest window" guess. Because
extraction is pure, re-running it over a recorded completion must be byte-identical (this is the harness-determinism
property, tested here for extraction and again end-to-end in H008).

## Steps

1. `bin/lab-arm-b-extract --completion <file> --incident <id> --representation <R0|R1|R2>`: locate the final tagged
   line. Accept exactly one of `COORDINATE:` or `REFUSAL:`. If both appear, neither appears, or multiple `COORDINATE:`
   lines appear -> refusal.
2. For a `COORDINATE:` line: parse `window` (int) and `lsn` (Postgres text); resolve via `bin/lab-coordinate` to
   `lsn_int` (integer), `wall_clock`, `snapshot`. If the LSN is unparsable, or resolves outside the incident's range,
   or the window is out of range -> refusal (not a clamp, not a nearest-match).
3. Emit the frozen `arm-coordinate` record for a determination (`arm=arm_b`, `representation=<...>`,
   `selection_inputs.read_injection_log=read_oracle_optimum=read_provenance=false`, `ledger_view=<blind view>`,
   `rationale` filled in H006), or a refusal record (`outcome="refusal"`, `arm_coordinate=null`) with the raw
   completion SHA-256 retained.
4. **Integer-LSN rule.** All comparison/resolution uses `(high<<32)+low`; include a test case with `3/9` vs `3/10` to
   prove no string comparison.
5. **Determinism.** Re-run extraction twice on the same recorded completion; assert byte-identical output.

## Negative test (required)

Modify a scratch copy of the extractor so that an unparsable/out-of-range coordinate falls back to the nearest valid
window (a coerced guess). Assert an end-to-end check catches that a refusal-worthy completion produced a coordinate
(the coerced-guess detector fires). Revert -> refusal-worthy completions record refusals again.
