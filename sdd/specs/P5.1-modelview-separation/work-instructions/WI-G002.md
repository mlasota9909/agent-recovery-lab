## Objective

Freeze the superseding amendment, build the two projection emitters (`model_view` and `reference`), and build the
guard that mechanically enforces Article XVII. After this task, there exists exactly one object P6 is allowed to hand
the model — one that provably cannot contain the recovery coordinate.

## Background (read before editing)

`bin/lab-repr-query` (F005) currently emits the full base envelope (`answer` + `content` + `telemetry` + ids). Do
**not** modify it — it is referenced by frozen F005 review artefacts, and G003/AC-P5.1-11 require the representations
and their query path to stay byte-identical. Instead, build thin wrappers that call `bin/lab-repr-query` and project
out the respective surface. Read `sdd/specs/P5.1-modelview-separation/contracts/representation-interface.amendment-1.md`
(which you freeze in step 1) for the exact `model_view` and `reference` shapes.

The guard's subtlety, get this right: the model's `content` legitimately contains LSN digits (R0's raw log lines, R2's
"Window 15 [12897001..12897850]" summary) — that is the *evidence* the model reads to derive the coordinate. The guard
must forbid the **structured pre-computed answer** (an `answer`/`reference` key, a `candidates` array, an answer-level
`last_safe_lsn_int`, or `first_lsn_int`/`last_lsn_int` presented as answer fields), **not** the appearance of a number
inside the `content` string. A guard that rejected LSN digits in `content` would make R0 impossible and would be wrong.

## Steps

1. Author and freeze `representation-interface.amendment-1.md` under `sdd/specs/P5.1-modelview-separation/contracts/`
   (content already drafted in this package; confirm it defines `model_view` = exactly six keys and `reference` =
   `{answer}`). Hash-record it in `logs/review/G002/`. Confirm the base `representation-interface.md` F001 hash still
   verifies (byte-identical).
2. Build `bin/lab-repr-modelview <incident> <representation> <probe> [params-json]`:
   - call `bin/lab-repr-query` for the same arguments;
   - project the response to exactly `{incident_id, representation, probe_id, params, content, telemetry}`;
   - drop `answer` entirely;
   - emit canonical JSON (sorted keys) so re-run is byte-identical.
3. Build `bin/lab-repr-reference <incident> <representation> <probe> [params-json]`:
   - call `bin/lab-repr-query`;
   - project to `{incident_id, representation, probe_id, answer}`;
   - emit canonical JSON. This is for parity/telemetry tests only.
4. Build `bin/lab-modelview-guard <model_view.json>`:
   - parse JSON; assert top-level keys are exactly the six model_view keys (fail, naming the offending key, otherwise);
   - assert absence of any `answer` or `reference` key at any depth;
   - assert absence of a structured coordinate-answer: no `candidates` key, no `last_safe_lsn_int`, and no
     `first_lsn_int`/`last_lsn_int` **as object fields** (their appearance inside the `content` *string* is allowed);
   - assert provenance-blindness: no `principal`/`usename`/`session_user`/UID token in any key or value;
   - exit 0 if clean; non-zero naming the first violation otherwise.
5. Run `bin/lab-repr-modelview` for R0/R1/R2 × all six probes; pipe each through `bin/lab-modelview-guard`; all pass.
6. Confirm `bin/lab-repr-reference` for PB-6 returns the `answer` (`candidates:[...]`) that the model_view does not.
7. Commit before gating. Update the checklist row for G002.

## Negative test (required)

Two injections, each proving the guard is real. **(a) Answer injection:** take a clean PB-6 model_view, splice the
`answer` object from `bin/lab-repr-reference` into it, run `bin/lab-modelview-guard`, confirm it exits non-zero naming
`answer` (or `candidates`); remove it and confirm exit 0. **(b) Provenance injection:** add `"principal":"lab_agent"`
into the model_view, confirm the guard exits non-zero naming the provenance token; remove it and confirm exit 0. Record
both. (AC-P5.1-07)
