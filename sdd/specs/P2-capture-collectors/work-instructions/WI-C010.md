## Objective

Provide the tiered acceptance gate for P2, re-verify that no prior contract changed, and write the architecture
handoff that records the ledger layout and the 500-op reconciliation result.

## Background

Every tranche ends in a gate that re-derives its criteria mechanically and prints per-tier totals — never a single
undifferentiated green (Article XIII). C010 also re-verifies the P0/P1/P1.1 gates and contract hashes to prove P2
disturbed nothing frozen, and produces the handoff a fresh P3 agent will read.

## Steps

1. Build `bin/lab-verify-p2` that runs every AC-P2 criterion, each re-derived from live state or committed artefacts,
   labelled tier M or tier A, and prints `TIER M <p>/<n> · TIER A <p>/<n> · TOTAL <p>/<n>`. Load-bearing criteria
   (AC-P2-05, 08, 09, 12, 13, 14) MUST be tier M. Exit non-zero if any criterion fails.
2. Re-verify prior gates and hashes:
   - `bin/lab-verify` 18/18, `bin/lab-verify-p1` 24/24, `bin/lab-verify-p1.1` 16/16, all exit 0;
   - P0 (R007) and P1 (W002/W010) contract hashes unchanged; the C001 `capture-completeness.md` hash matches its
     freeze.
3. Write `docs/P2-architecture-handoff.md`: the per-incident ledger layout (contract §1), the collectors and their
   units, the entry gate (`lab-ready`) and exit gate (`lab-ledger-account`), the 500-op reconciliation result as
   machine-readable fields (`ops`, `mapped`, `gaps`, `duplicates`), the measured snapshot interval and the resulting
   filesystem-granularity property, and the P3 entry condition and provenance-blind rule. **Do not** invert anti-goals
   — state plainly that P3 builds analytics (Arm A) and representations (Arm B), and that P2 deliberately did not.
4. Update `docs/p1-acceptance-memo.md` (or a P2 equivalent) only to append P2's acceptance; do not alter prior text.

## Negative test (required)

Introduce a transient failure of one load-bearing criterion — e.g. move `snapshots.json` aside so AC-P2-05's
snapshot-LSN check cannot pass — and assert `bin/lab-verify-p2` exits non-zero, names that criterion, and does **not**
report a green total. Restore and confirm exit 0. A gate that reports total-green while a load-bearing criterion is
unmet is a fail — the exact failure this project has been caught with three times.
