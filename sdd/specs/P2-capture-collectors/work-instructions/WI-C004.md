## Objective

Capture filesystem change evidence between snapshots using only stock ZFS facilities: a `zfs diff` walker producing
`fs_diff.tsv`, and a tree hasher reading `.zfs/snapshot/<snap>/` producing `fs_hashes.tsv`.

## Background

Per ADR-P2-4 there is no live filesystem daemon. Change evidence is derived after the fact from snapshots you already
take for the oracle. `zfs diff` gives the changed-path set; hashing files out of the read-only `.zfs/snapshot/` mount
gives content fingerprints for detecting modification and for the oracle's byte-level match. `zfs diff` cannot report
who changed a file — that is fine, provenance comes from the workload log, not the filesystem (Article II).

## Steps

1. Build `bin/lab-fs-capture` (discovering paths from `etc/lab.env`):
   - `diff <snap_from> <snap_to>`: run `zfs diff -H <ds>@<from> <ds>@<to>`, parse the tab-separated output, and append
     rows `snap_from  snap_to  change_type  path` to `fs_diff.tsv`. Change type is one of `+ - M R`.
   - `hash <snap>`: for each file in the protected subtree under `<mountpoint>/.zfs/snapshot/<snap>/`, compute sha256
     and append `snap  path  sha256` to `fs_hashes.tsv`.
2. Read snapshots read-only from `.zfs/snapshot/` — no mounting, cloning, loop devices, or `zfs send`.
3. Idempotence: re-running `diff`/`hash` for a pair/snapshot already recorded detects it and reports
   `"changed": false` rather than duplicating rows.

## Acceptance tests

| ID | Tier | Command | Expected |
| --- | --- | --- | --- |
| C004-1 | M | create/modify/delete three known files between two snapshots; `lab-fs-capture diff` | `fs_diff.tsv` lists exactly those three paths with correct change types `+ M -` (AC-P2-06) |
| C004-2 | M | `lab-fs-capture hash` on both snapshots; compare an unchanged file | identical sha256 across snapshots (AC-P2-07) |
| C004-3 | M | compare a modified file's hash across snapshots | sha256 differs, matching the known change (AC-P2-07) |
| C004-4 | M | inspect `bin/lab-fs-capture` for prohibited mechanisms | no `fanotify`/`inotify`, no `zfs send`/clone/loop mount |
| C004-5 | M | re-run `diff`/`hash` for the same pair | `"changed": false`; no duplicate rows |

## Negative test (required)

Induce a known modification to one file, then deliberately run the hasher against the **wrong** (pre-change) snapshot
and assert the recorded hash does **not** match the post-change content — then run it against the correct snapshot and
assert it does. This proves the hasher reads the specified point-in-time content rather than the live file. A hasher
that returns the live hash regardless of snapshot is a fail.
