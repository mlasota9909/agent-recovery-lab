## Objective

Prove the ledger is complete and exactly-once: reconcile a 500-operation workload against the ledger so that every
operation maps to exactly one ledger record — zero gaps, zero duplicates — and assert every remaining completeness
rule from the contract. This is the reason the tranche exists.

## Background

The capture-completeness contract §3–§4 defines completeness and the exactly-once mapping. C008 implements the check.
The mapping key uses only fields available to both sides **without** provenance (contract §5): DML by
`(xid, table, action, natural_key)`, DDL by `(xid, command_tag, object_identity)`. A valid reconciliation is a
bijection over the ledgerable operations. Gaps and duplicates are both failures. All LSN comparison is integer
`(high<<32)+low`, never string.

## Steps

1. Build `bin/lab-ledger-account <incident>` that, reading `workload.jsonl` and the ledger via `bin/lab-query`
   (default views, **no principal**):
   - **C-1 exactly-once**: build the mapping (contract §4); assert it is a bijection over the ledgerable ops. Report
     any gap (op with no record) and any duplicate (op with >1 record) explicitly.
   - **C-4 monotonic LSN**: assert `db.jsonl` records are non-decreasing by integer LSN.
   - **C-2 before-images**: assert every U/D record has a full `identity` (delegate to / reuse `lab-db-integrity`).
   - **C-3 DDL presence**: assert every workload DDL op has a `ddl` record.
   - **C-5 heartbeat resolvability**: for a sample of wall-clock times in the window, assert an LSN resolves within 1 s
     (reuse `bin/lab-coordinate`).
   - **C-6 snapshot anchoring**: assert every `snapshots.json` entry has a non-null LSN.
   - **C-7 filesystem coverage**: assert every filesystem op's path appears in `fs_diff.tsv` for the spanning pair.
2. Print one JSON report with a per-rule pass/fail and counts (`ops`, `mapped`, `gaps`, `duplicates`). Exit non-zero
   on any violation, naming the failing rule and the offending operations.
3. The mapping and every assertion MUST NOT read `principal`. Provide a separate, clearly-scoped scoring helper if the
   oracle needs principal-based classification — but the coverage logic here is provenance-blind.

## Negative test (required)

Three separate injected faults, each caught then reverted:
1. **Gap** — delete one change line from a scratch copy of `db.jsonl`; assert `lab-ledger-account` reports one gap and
   exits non-zero.
2. **Duplicate** — duplicate one change line; assert it reports one duplicate and exits non-zero.
3. **Provenance leak** — point the mapping at a principal-bearing view; assert the no-principal scan (C008-3) fails.
Revert each and confirm exit 0. A reconciliation that cannot detect a gap, a duplicate, or a provenance leak is a fail.
