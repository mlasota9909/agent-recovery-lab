## Objective

Produce a deterministic, seedable mixed workload whose every operation is logged to `workload.jsonl`, so C008 has a
known operation set to reconcile the ledger against exactly-once. This is the generic ledger-exercising workload of
ADR-P2-6 — **not** an SC scenario.

## Background

The reconciliation in C008 needs ground truth about what operations were actually issued. The workload generator is
that ground truth. It must be deterministic (same seed → identical operations) so runs are reproducible, and it must
label each operation with its originating principal — legitimate work as `lab_app`, damage-like operations as
`lab_agent` — because the oracle and the scoring path classify by principal. Per Article II that label is for scoring
only; the generator writes it as a fact and nothing in detection reads it.

## Steps

1. Build `bin/lab-capture-workload <incident> --seed <n> --ops 500` that, connected as the appropriate roles:
   - issues a deterministic mix of INSERT/UPDATE/DELETE across the scenario relations, plus at least one DDL
     (`ALTER`/`DROP`), driven entirely by the seed;
   - runs legitimate operations as `lab_app` and damage-like operations as `lab_agent`;
   - appends one object per operation to `workload.jsonl` with, at minimum:
     `{ op_index, xid, table, action, natural_key, principal, wall_clock }` — the fields C008's mapping rule (contract
     §4) needs, using the natural (primary) key so each op maps to a unique ledger record.
2. Determinism: two runs with the same seed produce **byte-identical** `workload.jsonl` (modulo xid/wall_clock, which
   are recorded as observed but excluded from the determinism comparison — state exactly which fields are compared).
3. Do not read `principal` anywhere except to set the connecting role and to write the label. No detection logic here.

## Negative test (required)

Run the generator twice with **different** seeds and assert `workload.jsonl` differs (proving the seed actually drives
the mix, not a fixed script). Then run twice with the **same** seed and assert identity. A generator that ignores the
seed — identical output regardless, or nondeterministic at a fixed seed — is a fail.

## Review bundle

Standard five, plus the two seed-A runs and `determinism-diff.log`.

## Operator review checklist

- [ ] Same seed → identical operation log (over the compared fields)
- [ ] Different seed → different log
- [ ] Each op carries a natural key and a principal; ≥1 DDL present
- [ ] Detection logic reads no principal; the label is written as a fact only
