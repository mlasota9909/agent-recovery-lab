# WI-C002 — `bin/lab-capture {start|stop|status}`: collector orchestration + session manifest

| **Depends on** | C001 |

## Objective

Bring the existing collectors up and down coherently for one incident window, behind the `lab-ready` entry gate, and
record a session manifest that names every collector and its output file.

## Background

The collectors exist individually (`bin/lab-consumer`, `bin/lab-heartbeat-writer`, the snapshot helpers). What is
missing is a single orchestrator that starts them in the right order, verifies each is actually appending (not merely
"started"), records a manifest, and stops them cleanly. `lab-capture` is that orchestrator. It must not reimplement a
collector; it composes them.

## Steps

1. Build `bin/lab-capture` with three subcommands, discovering all names/paths from `etc/lab.env`:
   - `start <incident>`: **refuse with a non-zero exit** unless `bin/lab-ready` exits 0, naming the failed condition.
     Then, in order: ensure the `lab-consumer@<incident>` unit is active; start the one-second heartbeat writer;
     start the snapshot loop (C003 owns its LSN anchoring — here just launch it). After start, verify each collector
     is **appending** (consumer: `db.jsonl` grows or `confirmed_flush_lsn` advances; heartbeat: a new row within 2 s;
     snapshot loop: process alive). Write `session.json` into the incident ledger with each collector's name, unit or
     PID, output file, and the open coordinate (`bin/lab-coordinate` now).
   - `stop <incident>`: bring collectors down in reverse order, close `session.json` with the close coordinate, and
     invoke the teardown path (C009 owns slot hygiene; call it, do not duplicate it).
   - `status <incident>`: print one JSON object with each collector's liveness re-derived from unit state **and**
     file growth — never trust "I started it".
2. `lab-capture` mutates only collector lifecycle and the ledger. It must never write victim data and never call a
   model.
3. Idempotence: `start` on an already-running session detects it and reports `"changed": false`; `stop` on an
   already-stopped session is a no-op success.

| ID | Tier | Command | Expected |

## Negative test (required)

Make one collector appear up but not appending (e.g. pause the heartbeat writer while leaving its unit "active", or
point it at a stale file). Assert `bin/lab-capture status` reports that collector **not** healthy because file growth
stalled — proving `status` re-derives liveness rather than trusting unit state. Restore and confirm it returns
healthy. A `status` that reports green on a stalled collector is a fail (this is the exact P0.1 slot-invalidation
class).

## Review bundle

Standard five, plus `session.json`, `status-active.json`, `refuse-when-not-ready.log`.
