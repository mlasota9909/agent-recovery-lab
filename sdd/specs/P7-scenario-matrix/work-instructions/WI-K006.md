## Objective

Build the orchestrator that runs one matrix cell end-to-end unattended — automatic reset tiers, incident scoping,
per-incident `archive/current` management — appending exactly one schema-valid results row per run, with ledger
idempotency and range containment holding per incident, and resumability so a restart never duplicates a recorded
cell.

## Background (read before editing)

This is the integrity keystone. The two-phase generate-incident / evaluate-arm harness and the reset tiers T0/T1/T2
(P0/P1) already exist; `bin/lab-matrix` composes them. The subtle correctness properties are the ones prior reviews
surfaced: after a reset the cluster can re-emit WAL segment names it already emitted (per-incident `archive/current`
scoping prevents silent archive corruption — the P0 finding); the replication slot lives in PGDATA and rewinds on
T1/T2 while the host ledger does not (so ledger idempotency + range containment must hold across a reset boundary — the
P1 carry-forward). A failed run is a row, not a crash (ADR-P7-5). One row per run conforms to the frozen
`results-row.md`.

## Steps

1. Write `bin/lab-matrix` that, given a cell `(scenario, timing, arm, representation, replicate_index)`: selects/loads
   the scenario's frozen incident (generating it via T0 if this is the first cell for a new scenario, else reusing it
   via T1/T2), evaluates the arm (arm_a via `bin/lab-rank`; naive via the comparator; arm_b via `bin/lab-arm-b` through
   the guarded model_view), scores single-coordinate determinations through the unchanged P4 path, and appends exactly
   one `results-row` carrying `scenario_id`/`timing_pattern`/`arm`/`representation`/`incident_id`/`replicate_index`.
2. Reset tiers are automatic between runs: T2 to re-evaluate an arm against a frozen incident; T1 to return to the
   pre-injection baseline; T0 only when starting a new scenario incident. Never touch SC-01.
3. Per-incident `archive/current`: point the WAL archive at the incident's own scope; assert a reset does not corrupt
   a prior incident's archive (re-emitted segment names land in the correct incident scope).
4. Ledger idempotency + range containment per incident: assert no LSN appears twice within an incident's ledger and
   the ledger's LSN range is contained by the incident's open/close coordinates, **including across a T1/T2 reset**.
5. Resumability: on restart, detect cells already recorded (by the cell key) and skip them without duplicating rows.
6. Emit `logs/review/K006/cell-trace.json` for one full cell (the end-to-end trace) and
   `logs/review/K006/idempotency.json` (the per-incident no-duplicate-LSN + range-containment proof across a reset).
7. Commit. Update the checklist row for K006.

## Negative test (required)

Simulate a duplicated LSN across a reset boundary (inject a ledger record whose LSN already exists in the incident,
after a T2 reset); assert the idempotency check **catches** the duplicate and fails the incident rather than accepting
a corrupt ledger. Revert -> idempotency holds. This is the P1 ledger-desync guard proven under the matrix.
