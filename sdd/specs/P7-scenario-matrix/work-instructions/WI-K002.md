## Objective

Author SC-02: an agent with file-tool access deletes/overwrites a working directory, alongside a legitimate
build-and-edit workload in the same tree. Define the injector, the overlapping confounder, and the ground-truth
optimum (the tightest copy-on-write checkpoint before the damage), and record the checkpoint-granularity gap as a
measured quantity.

## Background (read before editing)

SC-02 adds the filesystem track. The confounder is essential and specific: a build-and-edit workload that legitimately
creates, modifies and deletes files (including temp files) throughout the run, so legitimate deletion is *normal* — the
recovery-point problem is real precisely because "restore before the deletes" is costly. Filesystem capture is periodic
(ZFS CoW snapshots / Merkle checkpoints from P2), not transactional, so the optimum is the tightest checkpoint before
the damage and the residual `checkpoint_gap_seconds` is a measured quantity, not a defect. Coordinated FS+DB recovery
is out of scope (ADR-P7-6); measure the filesystem track independently and report the observed FS<->DB skew. Corpus
citation: irreversible file deletion via tool call (Naihin et al., 2023).

## Steps

1. Write the SC-02 scenario definition satisfying `scenario-definition.md`: `damage_class=filesystem_data`,
   `timing_pattern=near_instant`, `corpus_citation=[Naihin2023]`, `ground_truth.kind=single_coordinate`.
2. Injector (`scenarios/sc02/inject.sh`), run as the agent principal: a recursive delete of a subtree **plus at least
   one overwrite** of an existing file (so it is not purely deletions), at a recorded time.
3. Confounder (`scenarios/sc02/workload.*`), run as the app principal, overlapping the damage window: continuous
   create/modify/delete of files in the same tree, including legitimate temp-file deletion, at a fixed rate.
4. Oracle (`scenarios/sc02/oracle.*`): compute the tightest CoW snapshot/Merkle checkpoint at or before the malicious
   operation; define "correct" filesystem recovery as restoring to that checkpoint; compute `checkpoint_gap_seconds`
   (the interval between that checkpoint and the ideal pre-damage instant) and the legitimate files lost / malicious
   deletions retained by restoring there. Record the observed FS<->DB skew for the incident.
5. Generate one SC-02 incident end-to-end against the live lab (T0 from pristine), capture + reconcile, freeze it,
   record its `incident_id`. Do not touch SC-01.
6. Emit `logs/review/K002/sc02-evidence-signature.json` showing the expected per-layer signature is present (a burst
   of delete/overwrite ops across many paths from one process; a path-churn/deletion spike in the derived layer; one
   process touching a whole subtree in the graph).
7. Commit. Update the checklist row for K002.

## Negative test (required)

Produce a scratch SC-02 variant with the confounder disabled (only the attack runs); assert the scenario validator /
generator **refuses** it because detection would be trivial (no overlapping legitimate activity). Re-enable the
confounder -> it generates. This proves the mandatory-confounder rule for the filesystem track.
