## Objective

Freeze the two P7 contracts, re-measure the real full-cycle throughput on the current lab, and record a stratified run
plan with explicit per-cell replicate counts and a total N — before any scenario is authored or any run executed.
Record the entry gate.

## Background (read before editing)

"Maximum achievable will be attempted" is not a plan. `run-matrix-plan.md` replaces it with named
cells and per-cell replicate counts derived from a **measured** cycle time. The P0.1 figure of 49.335 s predated the
R005 reset guard (which stops/starts the cluster around a reset), so it is a floor, not a budget — re-measure it now.
`scenario-definition.md` makes every scenario machine-checkable, enforces the mandatory overlapping confounder, and
distinguishes `single_coordinate` (SC-01/02) from `set_and_earliest` (SC-03/04) ground truth. Read both contracts in
this package's `contracts/` line by line; this task freezes them as-is (or via a superseding amendment if a defect is
found — never by editing a frozen file).

## Steps

1. Copy `sdd/specs/P7-scenario-matrix/contracts/scenario-definition.md` and `run-matrix-plan.md` into place; validate
   the embedded example JSON parses; hash-freeze both into `logs/review/K001/` (record sha256).
2. Re-measure the full cycle on the current lab, distinguishing the two costs the plan needs: `generate_incident`
   (inject + capture + reconcile + freeze) and `evaluate_arm_t2` (evaluate one arm against a frozen incident via a T2
   reset). Run each >=3 times; record mean and spread. Use a throwaway incident that is torn down; **do not** touch the
   frozen SC-01 ledger.
3. Fix `K` (arm_b replicates per cell; default 5) and compute the stratified per-cell plan across the design space
   (scenario x timing x arm x representation), honouring: deterministic arms (arm_a, naive) get 1 recorded run per
   cell; arm_b gets K; the **SC-04 R0/R1/R2 ablation is fully replicated**; SC-01 cells are referenced from the banked
   results, not planned for re-run. Compute `total_planned_runs`.
4. Record the entry gate in `logs/review/K001/entry-gate.json`: `bin/lab-regression` result; that `bin/lab-ready` can
   reach exit 0 for incident generation (observed, then leave the lab as you found it); the banked SC-01 results are
   present (paths + row counts); the model runtime containment check (P6.1 redefinition) passes.
5. Emit `logs/review/K001/run-plan.json` (the frozen plan values: measured cycle seconds, K, per-cell table,
   `total_planned_runs`) and a short human-readable `run-plan.md`.
6. Commit. Update the checklist row for K001.

## Negative test (required)

Write a scratch scenario definition with `confounder.overlaps_damage=false` and run it through the schema validator;
assert the validator **refuses** it (the mandatory-confounder rule). Then set it true and assert it validates. This
proves the schema's central guard is live before any real scenario is authored.
