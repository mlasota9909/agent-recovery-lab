## Objective

Compute the honest scenario-specific findings from the complete results file: the SC-03 single-coordinate trade-off,
the SC-04 precision/recall + earliest-bounded commit, and — for any residual refusal or null cell — the Article XVIII
root-cause diagnosis from the verbatim completions.

## Background (read before editing)

SC-03 and SC-04 are `set_and_earliest` scenarios; reporting them honestly is the point (ADR-P7-3). SC-03: the
single-coordinate optimum removes the damage but discards legitimate DML committed during the migration — report both.
SC-04: there is no single coordinate; report precision/recall of identified malicious transactions and the earliest
correctly-bounded commit, computed against the K004 ground-truth set. Any cell that refuses or nulls must be
root-caused via `bin/lab-diagnose-refusal` (the J001 taxonomy) from the verbatim completions before it is reported —
never a bare null (Article XVIII). All values come from committed fields, never prose.

## Steps

1. SC-03 finding: from the results file + the K003 oracle, compute per arm the `single_coord_optimum_lsn`, the
   `legit_dml_sacrificed` at that coordinate, and `ddl_ops_retained`. Emit `logs/review/K008/sc03-finding.json`.
2. SC-04 finding: from the results file + the K004 precision/recall harness + `sc04-groundtruth.json`, compute per arm
   and representation `malicious_txn_precision`, `malicious_txn_recall`, `earliest_bounded_commit`, and (as a lower
   bound only) `coord_error_lsn`. Emit `logs/review/K008/sc04-finding.json`.
3. Residual-refusal diagnosis: for every cell with `outcome="refusal"` or a null result, run `bin/lab-diagnose-refusal`
   on the verbatim completion and record the J001-taxonomy cause (`grammar-noncompliance`, `vocabulary-mismatch`,
   `explicit-refusal`, `task-infeasible-claim`, `other`). If a representation refuses at 100% for a scenario under the
   corrected instrument, state it plainly as a candidate genuine finding (that representation is insufficient for that
   scenario) — do not hide it, do not coerce a determination. Emit `logs/review/K008/refusal-diagnosis.json`.
4. Cross-check: all findings are computed from committed results/arm-coordinate fields, not from any implementer prose.
5. Commit. Update the checklist row for K008.

## Negative test (required)

Two-part, one per headline finding:
(a) construct a scratch SC-03 finding claiming `legit_dml_sacrificed=0` while the ledger shows DML in the migration
window; assert the check catches it. (b) score SC-04 against a deliberately wrong malicious set and assert the
precision/recall check, re-deriving from `sc04-groundtruth.json`, catches the mismatch. Revert both -> computed
truthfully. This guards both scenario-specific headline metrics.
