## Objective

For each new scenario incident (SC-02/03/04), build the three representations R0/R1/R2 with the reused P5 builder, and
prove each is admissible, interface-parity-holding and guard-clean. Re-verify that SC-01's representations and banked
results are byte-identical/unchanged.

## Background (read before editing)

The ablation only means something if the three representations differ **only** in content, not in interface, and if
none leaks the answer or provenance (P5 identical-interface + P5.1 model_view/reference split + guard). P7 does not
change the representation builder or the guard; it runs them on the new incidents. SC-01's representations must remain
byte-identical to their P5/P5.1 close (the P6.1-review carry-forward) so the SC-01 cells stay comparable, and the
banked SC-01 results must be unchanged (ADR-P7-1).

## Steps

1. For each of SC-02/03/04's frozen incident: run the P5 representation builder to produce R0/R1/R2 under
   `var/repr/<incident>/`; produce the F006 admissibility manifest for each.
2. Prove interface parity per scenario: the `model_view` envelope from `bin/lab-repr-modelview` is identical across
   R0/R1/R2 except `content` (diff the six-key envelope for the recovery probe).
3. Prove guard-clean per scenario: `bin/lab-modelview-guard` accepts each `model_view` and there is no
   answer/reference/coordinate/provenance token in any of them.
4. Prove byte-identical rebuild per scenario: rebuild R0/R1/R2 and confirm identical hashes; confirm `built_by_model`
   is false where the representation records it (R2 summaries are deterministic templates, not model output).
5. Re-verify SC-01 unchanged: hash SC-01's R0/R1/R2 artefacts and compare to the recorded P5/P5.1 freeze; confirm the
   banked SC-01 results (P3 arm_a/naive, P6.1 arm_b) row files are byte-identical. Any drift is a blocker.
6. Emit `logs/review/K005/repr-admissibility.json` (per scenario: admissible, parity, guard-clean, rebuild-identical)
   and `logs/review/K005/sc01-unchanged.json` (SC-01 artefact + banked-result hashes vs recorded).
7. Commit. Update the checklist row for K005.

## Negative test (required)

Take one new scenario's R2 `model_view` and inject a `reference`/`answer` field into it; assert `bin/lab-modelview-guard`
**refuses** it before it could reach a model (Article XVII carries into the new scenarios). Revert -> guard-clean. This
proves the guard is enforced per scenario, not just for SC-01.
