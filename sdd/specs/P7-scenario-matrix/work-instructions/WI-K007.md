## Objective

Execute the full stratified matrix from the K001 plan, unattended, producing the complete results file: every planned
cell across scenario x timing x arm x representation x replicate, one schema-valid row per run, failures recorded as
rows, every arm-coordinate provenance-blind, single-coordinate determinations scored through the unchanged P4 path.

## Background (read before editing)

`bin/lab-matrix` (K006) runs a cell; K007 drives it across the whole plan and proves the unattended contract:
`total_rows = total_planned_runs`, partitioned into determinations, refusals and `run_failure`s, with no manual
intervention per run and no silent gap. Arm A and naive run on every scenario; Arm B (R0/R1/R2) runs on every scenario
through the guarded model_view; the SC-04 ablation is fully replicated. SC-01 cells are included by reference from the
banked results, not re-run. Every arm-coordinate must have `selection_inputs.read_*` all false (Article II); the model
sees only the guarded model_view (Article XVII); the P4 path is unchanged (its gate hash must still verify).

## Steps

1. Drive `bin/lab-matrix` across the K001 plan for SC-02/03/04 (and reference the banked SC-01 cells). Run it
   unattended; capture the run log.
2. For each run, one schema-valid `results-row` is appended. A run that cannot proceed records `outcome="run_failure"`
   with a `failure_reason` and the matrix continues.
3. After completion, assert `total_rows == total_planned_runs`; partition into determinations / refusals /
   run_failures; confirm the per-cell replicate counts match the plan (SC-04 ablation fully replicated).
4. Assert every arm-coordinate produced carries `selection_inputs.read_injection_log=read_oracle_optimum=read_provenance=false`;
   scan all model inputs/rationales for any principal/usename/session_user/UID token (must be none).
5. Assert single-coordinate determinations (SC-01/02 and any single-coordinate arm on SC-03) were scored through the
   unchanged P4 path; re-verify the P4 gate hash unchanged.
6. Confirm each run records its `timing_pattern`, and that the realized timing variants match the plan.
7. Emit `logs/review/K007/matrix-completeness.json` (planned vs recorded counts per cell; determinations/refusals/
   failures) and `logs/review/K007/provenance-blind-sweep.json` (the read_* and token-scan results).
8. Commit. Update the checklist row for K007.

## Negative test (required)

Inject a provenance token (a `usename` value) into one arm's model input for a single scratch run; assert the
provenance-blind sweep / guard **catches** it (the run is flagged and the sweep fails) rather than the run completing
silently. Revert -> the sweep is clean. This proves the Article-II guard holds across the matrix, not just on SC-01.
