## Objective

Replace the structurally-impossible against-frozen-headline regression with one that runs each prior gate against its
own pinned healthy fixture, and re-derive `bin/lab-verify-p3` so its regression criterion is both meaningful and
achievable — reaching an honest green. This is the task to read line by line: it defines what "prior code still works"
means from now on.

## Background (read before editing)

`AC-P3-18` today re-runs the five prior gates against `archive/current` pointed at the frozen SC-01 headline. That is
impossible to pass because the frozen state (consumer stopped) contradicts the live state P0's `lab-verify` requires.
The redesign has two independent parts that must not be conflated: (a) **against the headline**, only read-only
assertions — frozen contract hashes unchanged, every gate script present and read-only; (b) **prior-code-works**,
delegated to `bin/lab-regression` running each gate against its own pinned fixture in the live-equivalent state that
gate expects. `bin/lab-ready` exit 0 before any capture; wait on `bin/lab-barrier` after any reset. Article II binds:
no detection/mapping/ranking path reads `principal`.

## Steps

1. For each prior tranche whose gate needs a live-equivalent incident (at minimum P0/P1/P2/P2.1/P3), capture a small
   real incident through the normal pipeline, reconcile it with `bin/lab-ledger-account` (must be gaps=0,
   duplicates=0), and store it read-only under `fixtures/regression/<tranche>/` with a `provenance.json` (how/when
   captured, incident id, reconcile result). These are synthetic lab data (Article X). None is the headline incident.
2. Create `bin/lab-regression`: for each prior gate, place its fixture into the live-equivalent state the gate expects
   (e.g. for P0 `lab-verify`, start the consumer on the fixture incident and wait for the slot to drain via
   `bin/lab-barrier`), run the gate against it, and record PASS/FAIL with per-tier totals. Runs entirely read-only
   over the *evidence* (fixtures are read-only; any mutable working state lives under `logs/review/`). Never touches
   the headline incident.
3. Re-derive `bin/lab-verify-p3`'s regression criterion into two sub-checks: (a) read-only against-headline (all
   frozen contract hashes unchanged incl. `capture-completeness.md`; every `bin/lab-verify*` present and passes
   `bin/lab-gate-readonly-check`); (b) `bin/lab-regression` green across all prior gates. Preserve every other P3
   criterion unchanged. `bin/lab-verify-p3` must now reach an honest green with per-tier totals.
4. Confirm the SC-01 headline incident is byte-identical to its P3 close: hash its `db.jsonl` and its results rows and
   compare to the P3 recorded hashes. P3.1 must not have altered the headline.
5. Provenance-blindness check: run the regression and `bin/lab-verify-p3` against a principal-stripped copy of the
   fixtures/ledger and confirm outcomes are unchanged (AC-P3.1-15).
6. Update the P3.1 checklist row for Z003.

## Negative test (required)

**The regression signal is real:** in a scratch copy, break one prior gate (e.g. make `bin/lab-verify-p2`'s
before-image check always pass regardless of input, or corrupt its fixture's `db.jsonl`) and confirm
`bin/lab-regression` reports that gate FAIL and exits non-zero (AC-P3.1-09). Restore and confirm green. This proves the
new regression can actually catch a broken prior instrument — the property the old impossible design never had.
