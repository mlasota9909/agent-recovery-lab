## Objective

Provide a mechanical read-only enforcement harness, then make every `bin/lab-verify*` conform to Article XVI: remove
the `lab-verify-p1.1` write that caused the `PermissionError`, and rework `lab-verify-p2` AC-P2-17 so it operates on a
scratch copy under `logs/review/` instead of copying onto current evidence. No criterion is weakened.

## Background (read before editing)

The evidence root is the tree the ledger and incidents live under (discover its path from `etc/lab.env`; do not
guess). `logs/review/` is **not** under the evidence root and is the only place a gate may write. `lab-verify-p2`
AC-P2-17's intent is to prove a frozen ledger can be verified against a known state — that intent is preserved; only
its *destination* changes from current evidence to a scratch copy. `lab-verify-p1.1` must complete its check by
reading, never writing, the frozen `db.jsonl`.

## Steps

1. Create `bin/lab-gate-readonly-check <gate> [gate-args...]`:
   - build a recursive SHA-256 manifest of the evidence root into `logs/review/Z002/manifest.before`;
   - run the named gate (capturing its exit and output);
   - rebuild the manifest into `manifest.after`;
   - `diff` the two; if different, print the first changed path and exit non-zero; else exit with the gate's own exit.
   - The harness writes only under `logs/review/`.
2. Run it against each gate (`lab-verify`, `-p1`, `-p1.1`, `-p2`, `-p2.1`, `-p3`) and record which ones mutate
   evidence today. Expect `-p1.1` and `-p2` to be flagged.
3. Fix `bin/lab-verify-p1.1`: locate the write to the frozen `db.jsonl` (the `PermissionError` source) and replace it
   with a read-only derivation (copy into `logs/review/<id>/scratch/` if a mutable form is genuinely needed, then read
   from the scratch copy). The criterion it serves must still assert its original property.
4. Fix `bin/lab-verify-p2` AC-P2-17: instead of copying a frozen `db.jsonl` onto current evidence, copy it into
   `logs/review/<id>/scratch/` and run the check there. Current evidence must be untouched by the run.
5. Re-run `bin/lab-gate-readonly-check` against all six gates; all must now leave evidence byte-identical.
6. Confirm each fixed gate still reports its original totals (`-p1.1` 16/16, `-p2` 18/18) — read-only, no weakening.
7. Update the P3.1 checklist row for Z002. Commit before any results-row-producing command (there are none here).

## Negative test (required)

Two parts. **Harness detects a write:** add a throwaway gate that touches a file under the evidence root, run it under
`bin/lab-gate-readonly-check`, and confirm the harness reports the changed path and exits non-zero. Remove the
throwaway. **Harness itself is clean:** confirm running the harness against a known read-only gate (`bin/lab-verify`
after its fix) leaves evidence byte-identical — i.e. the harness does not itself mutate evidence. This proves the
enforcer both catches violations and is innocent.
