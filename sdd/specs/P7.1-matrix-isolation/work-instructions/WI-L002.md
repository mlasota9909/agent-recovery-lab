## Objective

Make independent incidents truly independent on the shared `labpool` pool, so that resetting or tearing down one
incident cannot destroy or alter another's recorded state. This closes the D1 root cause. **Execute only if
`logs/review/L001/decision.json` records `decision:FULL` and `operator_countersigned:true`.** If FALLBACK, stop and
record `not_executed` with the decision reason.

## Background (read before editing)

The root cause (L001) is T012 `zfs rollback -r` on the shared parent `labpool/victim`. The fix per ADR-P7.1-2 is
per-incident dataset subtrees with reset scoped to the incident subtree, and a transient per-incident cluster. Read
`contracts/incident-isolation.md` in full — it is the normative spec for this task and is frozen at this task's close.
Read `bin/lab-reset`, `lib/lab_matrix.py`, and the incident-generation path so you extend them rather than duplicate.

## Steps

1. Freeze `contracts/incident-isolation.md`: compute and record its SHA-256 in `logs/review/L002/contract-hash.txt`.
2. Implement per-incident dataset creation in the generation path: an incident X creates
   `labpool/victim/inc_<id>/{pgdata,protected}` (ADR-P7.1-2 / contract §2), starts a transient cluster against that
   pgdata on a per-incident port recorded in the incident record, and takes `@pre_injection`/`@post_capture` on the
   incident subtree. The pre-existing shared `labpool/victim/pgdata` (SC-01 provenance) is left byte-untouched.
2b. **Incident runtime record + selection helper (contract §9).** Generation writes `runtime/incidents/<id>.env`
   (`INC_ID`, `INC_DS`, `INC_PGDATA`, `INC_PROTECTED`, `INC_PG_PORT`, `INC_PG_SOCKET`, `INC_SLOT`, `INC_HEARTBEAT_PORT`).
   Create `lib/lab_incident_env.sh`, sourced **after** `etc/lab.env` by generation, `lab-reset`, `lab-coordinate`, the
   snapshot ticker, the heartbeat writer, the logical consumer, DB/filesystem capture, and the scenario drivers. It
   resolves the active incident (`--incident <id>` or `LAB_ACTIVE_INCIDENT`) and exports the `INC_*` overrides for that
   process only. Do not edit `etc/lab.env`. SC-01 has no runtime record and must not gain one.
2c. **Incident-derived filesystem path (contract §9).** SC-02 and any filesystem scenario read `INC_PROTECTED`; a
   hardcoded `/srv/protected` is removed and an unset `INC_PROTECTED` is a hard refusal (no fallback to the shared path).
3. Harden `bin/lab-reset` (contract §4): reset for incident X operates only on `labpool/victim/inc_<id>` and children,
   using non-recursive rollback per leaf (or `-r` scoped to the incident subtree). It MUST refuse, non-zero and naming
   the violation, any target resolving to `labpool/victim` (shared parent) or outside the named incident subtree, and
   MUST refuse the SC-01 incident. Do not change the `reset_tier` enum.
4. Implement `bin/lab-coordinate` resolution against the incident's own live cluster (contract §3): `--lsn/--time` for
   incident X reads X's heartbeat table on X's port. Resolving against another incident's cluster is prohibited.
5. Implement teardown (contract §6): destroy only `labpool/victim/inc_<id>`; retain the host-side evidence ledger,
   sealed `db.jsonl`, results rows and archive record.
6. Commit. Update the checklist row for L002.

## Negative test (required) — disposable-parent design (contract §10)

Do **not** run the old descendant-loop reset over live `labpool/victim` (that scope holds banked SC-01 data), and do
**not** assert that a plain `zfs rollback -r labpool/victim@…` destroys child-dataset snapshots — it does not, and such
a test would be scientifically false.

Instead: create a disposable parent `labpool/p7_1_negative` with two throwaway incident subtrees A and B (each with
`@pre_injection`). Run a scratch copy of the **old descendant-enumerating reset** scoped to `labpool/p7_1_negative` and
confirm B's snapshots are destroyed — reproducing the true P7 D1 mechanism. Then confirm the real guarded `bin/lab-reset`
refuses a shared-parent (`labpool/victim`) request, non-zero, naming the violation. Destroy `labpool/p7_1_negative`
afterwards; nothing under `labpool/victim` is touched. (AC-P7.1-07)

Also add a runtime-selection negative test: with `INC_PROTECTED` unset, a filesystem scenario command MUST refuse rather
than write to a shared/default path — proving the indirection is load-bearing, not decorative.
