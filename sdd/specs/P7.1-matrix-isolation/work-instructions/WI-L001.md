## Objective

Establish, from primary P7 evidence, that the multi-scenario matrix was hollowed by a shared-pool architectural
defect; record the constitutional principle that follows; and make a bounded, operator-countersigned go/no-go decision
(FULL isolation re-run vs documented FALLBACK) that protects the writing timeline. This task produces no isolation code
and no re-run — it produces the evidence and the decision that tell L002–L005 whether and how to proceed.

## Background (read before editing)

`docs/P7-architecture-handoff.addendum.md` §3.1 records the root cause: T012 `zfs rollback -r` on
`DS_PARENT=labpool/victim` is for one incident; the matrix ran three live incidents on that shared dataset; SC-02's
live T2 (`post_capture` `s_20260826T095606Z`) destroyed the SC-03/SC-04 snapshots. §3.2 records that the first
unattended run's 34 SC-03/SC-04 cells were all `run_failure` and were stripped so `total_rows` stayed 51. `docs/
P7-handoff.json` confirms the partition and the canonical incident IDs. Do **not** re-derive these as if unknown —
cite the addendum and the commits (`64e11dd`, `8321ea8`) it names.

The decision matters because the honest fix (per-incident isolation + a live validated re-run) is real work against a
finite writing budget. FULL attempts it; FALLBACK anchors on the already-validated SC-01 headline and corrects D2/D3 in
documentation only. The operator countersigns before L002 runs.

## Steps

1. Read the constitution; confirm eighteen articles in force. Append **Article XIX** exactly as worded in `plan.md`
   (§ "Constitutional change"). Update the article count and any index.
2. Read `docs/P7-architecture-handoff.addendum.md` (in full), `docs/P7-handoff.json`, and `bin/lab-reset` (T012
   semantics). Emit `logs/review/L001/root-cause.json` recording: the destroying operation (`zfs rollback -r` on
   `labpool/victim`), the destroyed snapshots (SC-03/SC-04), the cited commits, the count of stripped cells (34), and
   the resulting hollow partition. Every field must be traceable to a line in the addendum or the JSON (record the
   pointer).
3. Assess FULL feasibility concretely and record it in `logs/review/L001/feasibility.md`: (a) can per-incident dataset
   subtrees + a transient cluster be built on `labpool` without disturbing the banked SC-01 subtree? confirm the SC-01
   dataset path and that it is separable; (b) estimate the re-run cost from the P7 throughput
   (`P7-handoff.json.throughput`: `generate_incident` 63.4 s, `evaluate_arm_t2` 232.8 s) × the SC-02/03/04 cell count,
   and state it against the remaining time budget; (c) note the SC-03/SC-04 live snapshots are gone, so they must be
   regenerated once under isolation.
4. Write the decision to `logs/review/L001/decision.json` (canonical JSON, sorted keys):
   `{"decision":"FULL"|"FALLBACK","time_budget_basis":"<hours/weeks stated>","rerun_cost_estimate_min":<n>,
   "operator_countersigned":false,"fallback_plan":"<if FALLBACK: the doc-only corrections for L005>","rationale":"…"}`.
   Leave `operator_countersigned:false`; the operator sets it true out-of-band before L002. If FALLBACK, state that
   L002/L003/L004 are `not_executed` and L005 delivers documentation-only D2/D3 corrections with SC-01 as the sole
   validated headline.
5. Record ADR-P7.1-1..5 into the plan's decision record (or `logs/review/L001/adr.md` cross-linked from the plan) as
   worded in `plan.md`.
6. Commit. Update the checklist row for L001.
