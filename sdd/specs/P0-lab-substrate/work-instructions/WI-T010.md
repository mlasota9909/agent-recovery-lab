# WI-T010 — Heartbeat table and 1 Hz writer

| | |
| --- | --- |
| **Task** | T010 |
| **Phase** | E — Coordinate anchoring |

| **Blocks** | T011, T014 |
| **Serves** | FR-5.1, AC-14 |
| **Est.** | 45 min |

## Objective

Write one row per second carrying wall clock and current WAL LSN, so the evidence store gains a dense LSN-to-time index
for free.

## Why this small thing matters so much

An operator reports an incident in **wall-clock** terms ("around 14:20"). Recovery happens in **LSN** terms. Without a
dense mapping between the two you cannot turn an approximate human report into a database coordinate, and the analysis
engine has no anchor to search around. Because heartbeat rows flow through logical decoding like any other change, this
index arrives inside the evidence stream itself — no extra collector, no second timeline to reconcile (D-5).

## Steps

1. Ensure `lab_heartbeat` exists: `id bigserial primary key`, `at timestamptz not null default clock_timestamp()`,
   `lsn pg_lsn not null`. Add an index on `at` and on `lsn`.
2. Insert rows as `INSERT INTO lab_heartbeat (lsn) VALUES (pg_current_wal_lsn())`.
3. Write `bin/lab-heartbeat` with `--start`, `--stop`, `--status`, all JSON out. Prefer a small systemd unit or a
   supervised background loop in the guest; whichever you choose, `--status` must report whether it is running, the
   observed rate over the last 60 s, and the newest row's `at`/`lsn`.
4. Keep the write cheap. The heartbeat must not dominate the change stream: it is one small insert per second against a
   workload doing far more. Record the measured overhead.
5. Set the table to `REPLICA IDENTITY DEFAULT` — before-images are not needed here and would only add noise. State this
   choice.
6. Confirm heartbeat rows appear in the decoded stream with monotonically non-decreasing LSN.
7. Consider retention: heartbeat rows accumulate at 86,400/day. Add a documented pruning rule (for example, keep the
   current incident's rows and archive older ones), and note that pruning must never delete rows inside an incident
   window, because the oracle needs them.
8. Record `HEARTBEAT_TABLE`, `HEARTBEAT_HZ` in `lab.env`.

## Acceptance tests

| ID | Command | Expected |
| --- | --- | --- |
| T010-1 | `bin/lab-heartbeat --start` then `--status` | running, JSON out |
| T010-2 | after 60 s: count rows in the last minute | 55–65 (AC-14, ~1 Hz with tolerance) |
| T010-3 | `SELECT bool_and(lsn >= lag(lsn) OVER (ORDER BY id)) ...` | true (monotonic) |
| T010-4 | decoded stream during the window | heartbeat inserts present with LSN |
| T010-5 | `bin/lab-heartbeat --stop` then `--status` | not running |
| T010-6 | `--start` twice | second reports `"changed": false` |
| T010-7 | measured overhead | recorded, and small relative to workload |

## Negative test (required)

Stop the heartbeat writer, wait, and confirm that a wall-clock-to-LSN resolution across that gap is reported as a
**gap** (degraded/lower-confidence) rather than silently interpolated. The resolver is built in T011, so if it does not
exist yet, record the requirement explicitly in `observations.md` as an input to T011 and assert it there. Silent
interpolation across a heartbeat outage would fabricate a coordinate.

## Review bundle

Standard five, plus `heartbeat-rate.txt` (the 60 s measurement), `monotonicity-check.txt`,
`overhead-measurement.md`, `retention-rule.md`.

## Operator review checklist

- [ ] Rate is genuinely ~1 Hz, measured not assumed
- [ ] LSN is monotonic
- [ ] Heartbeat rows visible in the decoded stream
- [ ] Overhead measured and small
- [ ] Pruning rule cannot delete rows inside an incident window
- [ ] Gap handling requirement passed forward to T011
