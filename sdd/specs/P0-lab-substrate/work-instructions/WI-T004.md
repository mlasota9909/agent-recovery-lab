## Objective

Create the scenario database and its relations, set `REPLICA IDENTITY FULL` so before-images are decodable, and
install the DDL audit trail that makes schema change visible in the logical stream.

## Two traps this task exists to avoid

**Trap 1 — no before-images.** By default logical decoding emits only the primary key for `UPDATE`/`DELETE`. Without
before-images you cannot score "damaged data retained", because you never learn what the row used to contain. Fix:
`REPLICA IDENTITY FULL` on every scenario relation. AC-6 proves it by decoding a real `DELETE` and finding the old
tuple.

**Trap 2 — DDL is invisible.** Logical decoding does not emit DDL at all. SC-03 (runaway migration / schema damage)
would be silently unmeasurable. Fix (D-4): an event trigger on `ddl_command_end` writes a row into
`lab_ddl_audit`, and that table is part of the decoded set — so schema changes arrive **in the same stream, in correct
LSN order**, with no second pipeline to reconcile.

## Schema to create in `labdb`

Keep it minimal but sufficient for all four scenarios. Suggested shape, adjust only with a recorded reason:

- `lab_ledger` — the high-volume relation SC-01 deletes from and SC-04 drips corruption into. Include an integer key,
  an indexed `created_at`, a numeric amount, a text payload, and a `row_version` integer.
- `lab_reference` — a smaller relation used for joins and for SC-03 schema damage.
- `lab_ddl_audit` — `id bigserial`, `at timestamptz default clock_timestamp()`, `principal text`, `command_tag text`,
  `object_identity text`, `statement text`.
- `lab_heartbeat` — created here or in T010; if here, leave the writer to T010.

## Steps

1. Create `DB_NAME=labdb`. Record it in `lab.env`.
2. Create the relations above with sensible indexes. Seed `lab_ledger` with enough synthetic rows to make a mass
   `DELETE` meaningful (target roughly 1–5 million; record the actual count and the seeding time).
3. `ALTER TABLE ... REPLICA IDENTITY FULL` on `lab_ledger` and `lab_reference`.
4. Create the event trigger function as `postgres`, `SECURITY DEFINER`, inserting into `lab_ddl_audit` using
   `pg_event_trigger_ddl_commands()`. Record `session_user` as `principal`.
5. Create the event trigger on `ddl_command_end`.
6. Grant so that `lab_agent` (created in T008) will be able to *cause* audit rows but **not** read, update or delete
   `lab_ddl_audit`. `SECURITY DEFINER` is what makes this possible; note it explicitly in `observations.md`.
7. Record `DB_NAME` and `DDL_AUDIT_TABLE` in `lab.env`.

All data is synthetic (Article X). Do not import anything.

## Negative test (required)

Temporarily set `REPLICA IDENTITY DEFAULT` on `lab_ledger`, and record that the intended before-image assertion would
not be satisfiable in that state (you may simply document the property change and revert; the full stream proof lives
in T014). Then restore `FULL` and confirm. This demonstrates the setting is load-bearing rather than incidental.
