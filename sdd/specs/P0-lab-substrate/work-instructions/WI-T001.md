# WI-T001 — Probe host and guest, verify device attachment, write `etc/lab.env`

| | |
| --- | --- |
| **Task** | T001 |
| **Phase** | A — Discovery (stop-gate) |
| **Depends on** | nothing |
| **Blocks** | every other task |
| **Serves** | FR-1.1, FR-1.2, FR-1.3, AC-1, AC-2 |
| **Est.** | 30–45 min |

## Objective

Discover every fact the rest of the tranche needs, write them to `etc/lab.env`, and **verify whether `/dev/vdb` and
`/dev/vdc` are attached to the host or to `thesisvm01`**. Build nothing else.

## Why this is a stop-gate

The plan (D-1) assumes ZFS datasets live *inside* the guest, because `vdb`/`vdc` are virtio names and virtio disks are
what a KVM guest sees. If those devices turn out to be host-side, the entire storage topology and the reset design
change, and the plan must be amended before any pool is created. Creating a pool on the wrong side would be
discovered much later, as an inexplicable inability to snapshot the database atomically.

## Preconditions

1. `sudo` works on the host without an interactive prompt for the commands used here.
2. `ssh thesisvm01 true` succeeds without a password.
3. `sudo virsh list --all` shows `thesisvm01`.

Any failure is exit code 2 and a `BLOCKED` result. Do not attempt to create or start the VM.

## Steps

### 1. Create the skeleton

```bash
mkdir -p <repo>/{bin,etc,evidence,archive,basebackup,results,logs/review}
```

### 2. Probe the host

Record, do not assume: hostname; `lsb_release -ds`; kernel; whether `/dev/vdb` and `/dev/vdc` exist **on the host**;
`zfs version` if present on the host; `virsh list --all`; and the deploy-root filesystem type (expected `ext4`).

### 3. Probe the guest over SSH

Record: hostname; distro; kernel; `zfs version`; `lsblk -dno NAME,SIZE,TYPE`; existence and size of `/dev/vdb` and
`/dev/vdc`; whether either already carries a partition table, filesystem signature or ZFS label (`blkid`,
`sudo zpool labclear -n` style *read-only* probing only — **do not clear anything**); PostgreSQL major version
(`psql --version` and `pg_lsclusters` if available); the data directory (`SHOW data_directory`); the port; and free
space on the guest root.

### 4. Determine `DEV_LOCATION`

- Devices present in the guest and absent on the host -> `DEV_LOCATION=guest`. Expected. Proceed.
- Devices present on the host and absent in the guest -> `DEV_LOCATION=host`. **STOP.** Write the review bundle,
  report `BLOCKED`, and state plainly that the plan's D-1 assumption is contradicted and needs amendment.
- Present in both -> **STOP** and report the ambiguity with the evidence. Do not choose.
- Absent in both -> exit 2, `BLOCKED`.

### 5. Refuse to proceed on in-use devices

If either device already has a filesystem, partition table or foreign ZFS label, stop and report. Do not wipe
anything. Destroying data because a spec looked like it wanted a clean disk is exactly the failure class this
project studies.

### 6. Write `bin/lab-discover`

A single script (shell or Python 3) that performs steps 2–5, emits all findings as JSON on stdout, and writes/refreshes
`etc/lab.env` per `contracts/lab-env.md`. Idempotent: re-running overwrites with freshly discovered values and reports
`"changed": true|false`. It must never invent a value; unknown means exit 2.

Populate at minimum: `LAB_HOST`, `LAB_ROOT`, `VM_NAME`, `VM_SSH`, `VM_ADDR`, `DEV_A`, `DEV_B`, `DEV_LOCATION`,
`ZFS_VERSION`, `PG_VERSION`, `PG_DATA`, `PG_PORT`.

### 7. Make the config sourceable

`etc/lab.env` must be `KEY=value`, no spaces around `=`, no quotes unless the value contains spaces, no interpolation.
Verify with `bash -n` after wrapping, or by sourcing it in a subshell and echoing three keys.

## Acceptance tests

| ID | Command | Expected |
| --- | --- | --- |
| T001-1 | `bin/lab-discover \| python3 -m json.tool` | Valid JSON, no null required fields |
| T001-2 | `( set -a; . etc/lab.env; echo "$VM_NAME $PG_VERSION $DEV_LOCATION" )` | All three non-empty |
| T001-3 | `grep -c '^[A-Z_]*=' etc/lab.env` | >= 12 |
| T001-4 | `ssh $VM_SSH 'lsblk -dno NAME' \| grep -E 'vdb\|vdc' \| wc -l` | 2 |
| T001-5 | manual read of `DEV_LOCATION` | `guest`; anything else is a documented STOP |
| T001-6 | `bin/lab-discover >/dev/null && bin/lab-discover` | Second run succeeds, `"changed": false` |
| T001-7 | `ssh $VM_SSH "blkid $DEV_A; blkid $DEV_B"` | No filesystem/partition signature, or a documented STOP |

## Negative test (required)

Run `bin/lab-discover` with `VM_SSH` temporarily pointed at a non-existent host (e.g. via an env override, not by
editing `lab.env`). It MUST exit 2 with a message naming SSH reachability, and MUST NOT write a partial `lab.env`.
Restore, re-run, confirm success. Capture both.

## Review bundle

`logs/review/T001/` with `commands.log`, `acceptance.md`, `artefacts.md`, `lab.env.snapshot`, `observations.md`, plus
`discovery.json` (full probe output) and `negative-test.log`.
