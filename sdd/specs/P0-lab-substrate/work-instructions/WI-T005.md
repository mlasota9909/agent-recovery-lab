## Objective

Create the host-side evidence architecture and the incident-scoping mechanism, so that evidence is structurally
out-of-band and a T1 reset cannot corrupt a previous incident's WAL archive.

## The subtle bug this task prevents

After a T1 reset the cluster rewinds and replays **the same timeline**, re-emitting WAL segment names it has already
emitted — with different contents. A single flat archive directory would silently accept some of those and reject or
overwrite others. The corruption would not surface until a PITR attempt in P4, days later, and would be extremely hard
to diagnose. Fix (D-3): `archive_command` always writes to `archive/current/`, and the host repoints that symlink at a
fresh per-incident directory before each run. The archive command also refuses to overwrite.

## Directory layout to create on the host

```
<repo>/
  evidence/<scenario>/<incident>/     0750 mlasota   (db.jsonl, fs_diff.tsv, fs_hashes.tsv, snapshots.json, ...)
  archive/<incident>/                 0750 mlasota   per-incident WAL segments
  archive/current -> <incident>/      symlink, host-managed, repointed by lab-incident
  basebackup/<incident>/              0750 mlasota
  results/                           0750 mlasota   (P1 owns the schema)
```

## Steps

1. Create the four roots with mode 0750 owned by `mlasota`. Victim principals must have no access (proven in T009).
2. Decide and implement the **one append path** from guest to host. Options, in order of preference:
   - a dedicated SSH channel from the guest's `postgres` user to a host account whose authorized-keys entry is
     restricted to a single append-only receiving command (`command=` restriction, `no-port-forwarding`, `no-pty`);
   - failing that, a read-only-for-victim NFS/9p export mounted at `ARCHIVE_MOUNT_IN_VM` where only append is allowed.
   Record which you chose and why in `observations.md`. The requirement is: the victim can add a new segment and can do
   nothing else — not list other incidents, not read evidence, not overwrite.
3. Mount/expose the sink inside the guest at `ARCHIVE_MOUNT_IN_VM`, placed under `/var/lib/postgresql/` with mode 0700
   owned by `postgres`, so `lab_app` and `lab_agent` are blocked by directory traverse permission at the OS level
   rather than by convention.
4. Write `bin/lab-incident`:
   - `--new --scenario SC-0n` allocates an incident id (`SC-0n_YYYYmmddTHHMMSSZ`), creates the evidence, archive and
     basebackup directories, repoints `archive/current`, and prints the incident record as JSON;
   - `--current` prints the active incident;
   - `--list` prints all incidents.
   Idempotent for `--current`/`--list`; `--new` always creates a new id.
5. Implement the archive receiving script with **overwrite refusal**: if the target segment file already exists, exit
   non-zero without modifying it. No `cp -f`, no `|| true`.
6. Write a `README-evidence.md` into `evidence/` stating the immutability rule: files are append-only while open and
   `0444` once closed; no process other than the capture CLIs writes there.
7. Record `EVIDENCE_ROOT`, `ARCHIVE_ROOT`, `ARCHIVE_CURRENT`, `BASEBACKUP_ROOT`, `RESULTS_ROOT`,
   `ARCHIVE_MOUNT_IN_VM` in `lab.env`.

## Acceptance tests

| ID | Command | Expected |
| --- | --- | --- |
| T005-1 | `stat -c '%U %a' evidence archive results basebackup` | `mlasota 750` for each |
| T005-2 | `bin/lab-incident --new --scenario SC-01 \| python3 -m json.tool` | valid JSON with an incident id |
| T005-3 | `readlink -f archive/current` | resolves to the new incident dir |
| T005-4 | `bin/lab-incident --new --scenario SC-01` twice | two distinct ids, `current` follows the second (AC-9) |
| T005-5 | write a segment, then attempt the same name again | second attempt exits non-zero, file unchanged (AC-8 prep) |
| T005-6 | `ssh $VM_SSH "sudo -u lab_agent ls $ARCHIVE_MOUNT_IN_VM"` | permission denied |
| T005-7 | `bin/lab-incident --current` | matches the most recent `--new` |

## Negative test (required)

As the guest's `postgres` user, attempt through the append channel to (a) list a *different* incident directory and
(b) overwrite an existing segment. Both MUST fail. Capture both refusals. If either succeeds, the isolation claim
is false and the task is not done.

## Review bundle

`overwrite-refusal.log`, `incident-scoping.log`.

- [ ] Overwrite is refused with a non-zero exit, not silently skipped
- [ ] `lab_agent` cannot even list the archive mount
- [ ] Two incidents produce disjoint archive scopes
- [ ] Evidence roots are not victim-accessible
