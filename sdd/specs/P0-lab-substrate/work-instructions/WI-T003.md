# WI-T003 — Relocate the PostgreSQL data directory onto `DS_PGDATA`

| | |
| --- | --- |

| **Phase** | B — Copy-on-write storage |
| **Depends on** | T002 |

| **Serves** | FR-2.2 |

## Objective

Move the live PostgreSQL data directory onto the ZFS dataset so that database state is captured by the same recursive
snapshot as the protected filesystem. This is the riskiest task in the tranche: a botched move corrupts the cluster.

## Safety rules (non-negotiable)

1. Stop PostgreSQL **before** copying. Never copy a running data directory.
2. Copy, verify, then switch. **Do not delete the original** until the acceptance tests pass; rename it aside.
3. Preserve ownership, permissions, ACLs and extended attributes exactly: `rsync -aHAX --numeric-ids`.
4. If anything fails, restore the original path and report `FAIL`. Do not attempt clever repairs.

## Steps

1. Source `lab.env`. Record the current data directory from the running server (`SHOW data_directory`) and confirm it
   matches `PG_DATA`.
2. Capture a pre-move baseline: `pg_lsclusters`, `SELECT version()`, database list, and `du -sh` of the data directory.
3. Stop the cluster. Confirm no `postgres` process holds the directory (`pgrep`, `fuser`).
4. Mount `DS_PGDATA` at a staging path, copy with `rsync -aHAX --numeric-ids`, then compare with
   `rsync -aHAXn --delete --itemize-changes` and require an empty diff.
5. Rename the original to `${PG_DATA}.pre-zfs`, then set the dataset's mountpoint to `PG_DATA` and mount it.
6. Verify ownership is `postgres:postgres` and mode `0700` on the data directory.
7. Start the cluster. Confirm it accepts connections, the database list matches, and `SHOW data_directory` returns
   `PG_DATA`.
8. Only after all acceptance tests pass, note in `observations.md` that `${PG_DATA}.pre-zfs` may be removed manually
   by the operator. **The agent does not delete it.**

Idempotence: if `PG_DATA` is already a ZFS mount from `DS_PGDATA` and the cluster is healthy, report
`"changed": false`.

## Acceptance tests

| ID | Command | Expected |
| --- | --- | --- |
| T003-1 | `findmnt -no SOURCE $PG_DATA` | `labpool/victim/pgdata` |
| T003-2 | `sudo -u postgres psql -Atc 'show data_directory'` | equals `PG_DATA` |
| T003-3 | `sudo -u postgres psql -Atc 'select count(*) from pg_database'` | matches pre-move baseline |
| T003-4 | `stat -c '%U:%G %a' $PG_DATA` | `postgres:postgres 700` |
| T003-5 | `rsync -aHAXn --delete --itemize-changes <orig>/ $PG_DATA/` | no differences |
| T003-6 | `sudo -u postgres psql -c 'create table t3(x int); drop table t3;'` | succeeds |
| T003-7 | `pg_lsclusters` | cluster online on `PG_PORT` |
| T003-8 | re-run task script | `"changed": false` |

## Negative test (required)

Attempt the copy step with the cluster **running** in a scratch copy of the script, or simulate a mid-copy failure,
and confirm the script refuses / aborts and leaves the original data directory in place and serving. Capture it. Then
run the real move.

## Review bundle

Standard five, plus `pre-move-baseline.txt`, `rsync-verify.txt`, `post-move-checks.txt`.

## Operator review checklist

- [ ] Cluster was stopped before the copy (visible in `commands.log`)
- [ ] `rsync` verification diff is genuinely empty
- [ ] Original directory still exists, renamed aside, not deleted
- [ ] Cluster is online and `data_directory` is the ZFS path
- [ ] Negative test shows a running-cluster copy is refused
