# WI-T015 — Full acceptance suite, idempotence sweep, freeze contracts

| | |
| --- | --- |
| **Task** | T015 |
| **Phase** | G — Verification and freeze |
| **Depends on** | T012, T013, T014 |
| **Blocks** | P1 |
| **Serves** | AC-1 … AC-18 |
| **Est.** | 1.5 h |

## Objective

Prove the whole tranche in one command, sweep every script for idempotence and hardcoded values, and freeze the three
contracts so P1 can build on stable ground.

## Steps

1. Write `bin/lab-verify` that runs **every** acceptance criterion AC-1 to AC-18 from `spec.md`, re-using the
   per-task proofs where they exist rather than reimplementing them. Emit JSON: one entry per AC with id, command,
   expected, observed, PASS/FAIL, plus a summary. Exit 0 only if all pass.
2. **Idempotence sweep (AC-18).** Re-run every task script in order and confirm each reports `"changed": false` and
   exits 0, destroying nothing. Any script that is not safe to re-run is a defect to fix now, because P1's batch
   execution will re-run things constantly.
3. **Hardcode sweep (AC-1).** Grep `bin/` for values that belong in `lab.env`: the VM name, guest address, device
   paths, pool and dataset names, PostgreSQL version and data directory, host paths, role names, slot name. Any literal
   match outside `lab-discover` is a violation. Report findings and fix them.
4. **Constitution audit.** For each Article, state in one line how the tranche complies, with a pointer to the
   artefact that shows it. Any Article you cannot evidence is an open item, not a pass.
5. **Prohibition audit (Article V).** Grep for `fanotify`, `inotify`, `pg_waldump`, `zfs send`, `zfs receive`,
   `CREATE PUBLICATION`, and any loop-mount or clone usage. Expected: zero occurrences in the analysis path.
   `pg_waldump` may appear only in a clearly-labelled cross-check utility.
6. **End-to-end rehearsal.** Without building any P1 logic, rehearse the mechanical loop to prove the substrate holds
   together: allocate an incident, start heartbeat and capture, take `@pre_injection`, run a trivial legitimate change
   as `lab_app`, run a trivial damaging change as `lab_agent`, snapshot `@post_capture`, resolve a coordinate for the
   damage time, reset `--tier t1`, confirm damage gone and evidence intact, reset `--tier t2`, confirm damage back.
   Time the whole cycle — this number tells you your achievable run throughput, which is what replaces "as many as
   possible" with a real sample-size plan.
7. **Freeze the contracts.** Mark `contracts/coordinate.md`, `contracts/lab-env.md` and `contracts/cli.md` as FROZEN
   with today's date. Note that P1 will add the results-row contract alongside them.
8. Write `specs/P0-lab-substrate/COMPLETION.md`: what was built, every AC result, measured timings (snapshot, rollback
   per tier, full cycle), the known limitations, and the open items for P1.

## Negative test (required)

Deliberately break one acceptance criterion — for example, chmod the evidence root so a victim principal can read it —
and confirm `bin/lab-verify` goes **red** on precisely that AC and exits non-zero. Restore and confirm green. A
verification suite that cannot fail is worthless (Article VIII), and this is the last chance to prove the whole suite is
honest.

## Review bundle

`prohibition-sweep.txt`, `constitution-audit.md`, `end-to-end-rehearsal.log`, `timings-summary.md`,
`negative-verify-red.log`, and `COMPLETION.md`.
