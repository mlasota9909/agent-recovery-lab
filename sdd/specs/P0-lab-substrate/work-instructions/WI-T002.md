# WI-T002 — Create `labpool` and the parent/children dataset layout

| | |
| --- | --- |
| **Task** | T002 |
| **Phase** | B — Copy-on-write storage |
| **Depends on** | T001 (`DEV_LOCATION=guest`) |
| **Blocks** | T003, T011, T012, T013 |
| **Serves** | FR-2.1, FR-2.2, FR-2.3, AC-3 |
| **Est.** | 30 min |

## Objective

Inside `thesisvm01`, create one ZFS pool across `DEV_A` and `DEV_B`, with a parent dataset and two children, so that a
single recursive snapshot captures the database and the protected filesystem atomically.

## Why parent-plus-children, not two siblings

`zfs snapshot -r labpool/victim@X` is atomic across descendants of one parent. Sibling datasets snapshotted with two
commands are not simultaneous, and the cross-layer coordinate would then be approximate — which would quietly
undermine the very measurement the experiment rests on (D-1).

## Layout to create

```
labpool                          (pool, both devices)
+-- labpool/victim               (parent; recursive snapshot target = DS_PARENT)
     |-- labpool/victim/pgdata      -> mounted at PG_DATA         (T003 moves data in)
     +-- labpool/victim/protected   -> mounted at MNT_PROTECTED   (/srv/protected)
```

## Steps

1. Source `etc/lab.env`. Abort (exit 2) if `DEV_LOCATION != guest`.
2. Re-verify both devices are still free of signatures. If not, stop.
3. Choose a pool topology and **record the reasoning in `observations.md`**: a stripe across both devices maximises
   space and speed; a mirror gives redundancy the experiment does not need. Default to **stripe**, because this is a
   reproducible lab whose ground truth lives on the host, not a production system. Do not silently pick one — state it.
4. Create the pool with `ashift=12`, `compression=lz4`, `atime=off`, `xattr=sa`, and `recordsize` left at default for
   the parent. Rationale for `lz4`: it reduces snapshot and diff I/O with negligible CPU cost and does not affect
   `zfs diff` semantics.
5. Create `DS_PARENT`, then the two children. Set `DS_PGDATA` `recordsize=8K` to match the PostgreSQL page size.
   Leave `DS_PROTECTED` at default `recordsize=128K`.
6. Ensure `snapdir=visible` on the parent and children, so `.zfs/snapshot/` is directly readable (FR-2.4 depends on
   this, and it is the reason no clones or loop mounts are needed).
7. Create `MNT_PROTECTED` and confirm mount points. Do **not** yet move the Postgres data directory — that is T003.
8. Take a throwaway recursive snapshot and time both snapshot and rollback. Record the timings, then destroy the
   throwaway.
9. Append `ZPOOL`, `DS_PARENT`, `DS_PGDATA`, `DS_PROTECTED`, `MNT_PROTECTED` to `etc/lab.env`.

Idempotence: if the pool and datasets already exist with the right properties, report `"changed": false` and pass.
Never destroy an existing pool to recreate it.

## Acceptance tests

| ID | Command (in guest) | Expected |
| --- | --- | --- |
| T002-1 | `zpool status labpool` | ONLINE, both devices present, no errors |
| T002-2 | `zfs list -r labpool` | Parent plus exactly two children |
| T002-3 | `zfs get -H -o value snapdir labpool/victim` | `visible` |
| T002-4 | `zfs get -H -o value recordsize labpool/victim/pgdata` | `8K` |
| T002-5 | `zfs get -H -o value compression,atime labpool/victim` | `lz4`, `off` |
| T002-6 | timed `zfs snapshot -r labpool/victim@t` | < 2 s (AC-3) |
| T002-7 | timed `zfs rollback -r labpool/victim/protected@t` | < 5 s (AC-3) |
| T002-8 | `mountpoint /srv/protected` | is a mountpoint |
| T002-9 | re-run the task script | `"changed": false`, exit 0 |

## Negative test (required)

Attempt to create the pool again *without* idempotence handling, or simulate a missing device by pointing `DEV_B` at a
non-existent path in a subshell. The script MUST exit non-zero naming the missing device and MUST NOT partially
create or degrade the pool. Capture the output.

## Review bundle

`logs/review/T002/` with the standard five files, plus `zpool-status.txt`, `zfs-properties.txt`, `timings.md`
(snapshot/rollback measurements), and the topology decision recorded in `observations.md`.
