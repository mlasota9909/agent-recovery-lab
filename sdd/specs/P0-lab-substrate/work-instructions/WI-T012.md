## Objective

Implement `bin/lab-reset --tier t0|t1|t2`, returning the victim to a known state in seconds while leaving host-side
evidence intact and re-usable.

## Why T1 is the tier that makes the experiment valid

The central claim is comparative: representation R0 versus R1 versus R2, at fixed scenario and fixed model. If each arm
regenerated its own baseline and its own concurrent legitimate workload, the arms would differ by more than the
representation and **the ablation would be confounded**. T1 lets you inject the incident once and evaluate every arm
against byte-identical evidence (D-7). T2 then lets you iterate on analysis and restore logic without re-running the
incident at all, which is where most of your debugging time will actually go.

## Tier semantics

| Tier | Target | Retains | Typical use |
| --- | --- | --- | --- |
| `t0` | `@pristine` | nothing but schema baseline | first run of a scenario; after changing schema or workload profile |
| `t1` | `@pre_injection` | quiescent baseline + legitimate work history, **no damage** | **default** between ablation arms |
| `t2` | `@post_capture` | everything incl. damage and captured evidence | iterating analytics / restore without re-injecting |

## Steps

1. Implement as `zfs rollback -r` against `DS_PARENT` for all three tiers, so one code path serves all (ADR-005
   refinement: T0 as ZFS rollback rather than a libvirt snapshot, for speed and shared code; the libvirt snapshot
   remains only as a coarse rebuild fallback — record this).
2. **Stop PostgreSQL before rollback and start it after.** Rolling back a dataset under a running cluster will corrupt
   it. Verify no `postgres` process holds the data directory before proceeding.
3. Do not touch anything under `EVIDENCE_ROOT`, `ARCHIVE_ROOT`, `BASEBACKUP_ROOT` or `RESULTS_ROOT`. Reset rewinds the
   **victim only**. Assert this after every reset (FR-6.4).
4. Handle the heartbeat writer: stop it before rollback, restart after, and note the resulting heartbeat gap in the
   incident record so T011's gap rule sees it rather than interpolating across it.
5. `zfs rollback` destroys snapshots **newer** than the target. That is intended for the victim, but it means the
   snapshot manifest must be reconciled: mark rolled-away snapshots as invalidated in `snapshots.json` rather than
   silently leaving stale entries that a resolver might later select. This is a real correctness trap.
6. Emit JSON: tier, target snapshot, elapsed ms, whether the cluster restarted cleanly, the heartbeat gap introduced,
   and the list of invalidated snapshots.
7. Time every tier. Record the measurements.

## Acceptance tests

| ID | Command | Expected |
| --- | --- | --- |
| T012-1 | `bin/lab-reset --tier t1` | JSON; elapsed < 5 s; cluster online (AC-17) |
| T012-2 | after t1: query `lab_ledger` | legitimate history present, damage absent |
| T012-3 | after t1: `ls $EVIDENCE_ROOT/...` | evidence untouched (FR-6.4) |
| T012-4 | after t1: archive contents | intact, byte-identical |
| T012-5 | `bin/lab-reset --tier t2` | damage present again, evidence intact |
| T012-6 | `bin/lab-reset --tier t0` | baseline only |
| T012-7 | `bin/lab-snapshots` after a rollback | rolled-away snapshots marked invalidated, not silently listed |
| T012-8 | `bin/lab-coordinate --snapshot <invalidated>` | exits non-zero |
| T012-9 | re-run same tier twice | idempotent, second is a no-op or a clean repeat |

## Negative test (required)

Attempt a rollback **without stopping PostgreSQL** in a scratch copy of the script and confirm the real script refuses
with a non-zero exit naming the running cluster. Separately, confirm that after a rollback the coordinate resolver
cannot select an invalidated snapshot — selecting one would silently produce coordinates against state that no longer
exists. Capture both.

## Review bundle

Standard five, plus `tier-timings.md`, `evidence-intact-proof.txt` (checksums before and after a reset),
`invalidated-snapshots.json`, `negative-running-cluster.log`.

## Operator review checklist

- [ ] Cluster stopped before rollback, restarted after, verified
- [ ] Evidence and archive provably untouched (checksums, not assertion)
- [ ] Invalidated snapshots cannot be resolved
- [ ] Heartbeat gap recorded, not hidden
- [ ] All three tiers timed
