## Objective

Make it impossible for the evidence machinery to take the victim down mid-experiment, and make archive overwrite
refusal an explicit, tested property.

## The failure mode being prevented

An unconsumed logical replication slot retains WAL **forever**. If the host-side consumer dies during an unattended
batch of runs, the victim's disk fills, PostgreSQL stops, and an entire night of matrix execution is lost — and every
partially captured incident is suspect. This is a boring operational failure that would cost real days in a 7-week
schedule.

## Steps

1. Set `max_slot_wal_keep_size` to a bounded value (`SLOT_MAX_WAL_KEEP`, suggest `8GB`, adjust to the guest's free
   space and record the reasoning). Beyond this, PostgreSQL invalidates the slot rather than filling the disk.
2. Write `bin/lab-slot`:
   - `--status` prints JSON: slot name, plugin, `active`, `restart_lsn`, `confirmed_flush_lsn`, retained bytes
     (`pg_current_wal_lsn() - restart_lsn`), and a boolean `over_threshold`;
   - `--create` / `--drop` manage the slot idempotently;
   - `--assert-healthy` exits non-zero if the slot is inactive when it should be active, or if retained bytes exceed a
     warn threshold. This is the pre-run check every later batch script calls.
3. Add a guest-side disk-space guard to `--assert-healthy`: exit non-zero if free space on the pool is below a stated
   floor.
4. Harden the archive receiving script from T005: overwrite refusal must be explicit and tested, with a distinct exit
   code from a genuine I/O error so the two are distinguishable in `pg_stat_archiver` triage.
5. Document in `observations.md` what happens if a slot **is** invalidated: the incident is void and must be re-run.
   State it plainly so it is not discovered as a mystery later.

## Acceptance tests

| ID | Command | Expected |
| --- | --- | --- |
| T007-1 | `psql -Atc 'show max_slot_wal_keep_size'` | equals `SLOT_MAX_WAL_KEEP` |
| T007-2 | `bin/lab-slot --status \| python3 -m json.tool` | valid JSON incl. retained bytes (AC-10) |
| T007-3 | `bin/lab-slot --assert-healthy` with consumer running | exit 0 |
| T007-4 | `bin/lab-slot --assert-healthy` with consumer stopped and lag grown | exit non-zero |
| T007-5 | re-send an existing WAL segment name | non-zero, dedicated exit code, file byte-identical (AC-8) |
| T007-6 | simulate low free space | `--assert-healthy` exits non-zero |
| T007-7 | `bin/lab-slot --create` twice | second reports `"changed": false` |

## Negative test (required)

Stop the host consumer, generate enough WAL to exceed the warn threshold, and show `--assert-healthy` failing with a
clear message. Then restart the consumer and show it passing. Separately, prove the overwrite refusal by checksumming a
segment before and after a re-send attempt — the checksums must match. Capture all of it.

## Review bundle

Standard five, plus `slot-status-samples.json`, `lag-negative-test.log`, `overwrite-checksums.txt`.

## Operator review checklist

- [ ] Retention is genuinely bounded; the value is justified against free space
- [ ] `--assert-healthy` fails for both lag and low disk
- [ ] Overwrite refusal proven by checksum, not by assertion
- [ ] Slot-invalidation consequence is documented
