# WI-Q002 — Build the deterministic scale generator

**Task:** Q002 · **ACs:** AC-P10-02, AC-P10-03, AC-P10-07 · **Est:** 2 days

## Goal
`bin/lab-scale-generate --scenario SC-01 --target <tokens> --seed 42` produces a padded incident ledger that hits the canonical-token target by adding legitimate activity only, preserving all C1 invariants.

## Steps
1. Load the frozen SC-01 incident ledger read-only. Never mutate it; write padded ledgers to `incidents/scaled/sc01-s<target>/`.
2. Generate legitimate padding activity of the kinds already in SC-01 (inserts/updates on the same relations; protected-subtree file writes), placed deterministically from `(seed, target)` only — MUST NOT read `injection_log.json` or the oracle.
3. Interleave padding across the timeline (before and after the malicious window) so the malicious window is embedded in legitimate traffic at every scale. Record the malicious window's relative position for each target.
4. Stop adding padding when measured canonical_tokens for R0 reaches the target (±2%). Record actual canonical_tokens.
5. Recompute the oracle optimum on the padded incident; assert it equals the frozen SC-01 optimum byte-for-byte.

## Acceptance tests
- **AC-P10-02:** run twice with same `(target,42)` → padded ledgers byte-identical (diff empty).
- **AC-P10-03:** for every target, padded oracle optimum == frozen SC-01 optimum.
- **AC-P10-07:** the R0/R2 model_view built from a padded ledger passes `lab-modelview-guard`.

## Negative test (AC-P10-03)
- Force the generator to inject ONE damage row into padding; assert the recomputed optimum MOVES and the generator refuses to emit the incident (fails closed). Remove the injection.

## Review bundle
Two-run diff proof, per-target optimum-equality table, guard pass log, the damage-injection refusal transcript.
