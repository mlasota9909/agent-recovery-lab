# WI-R003 — Re-parse and re-score the banked set

**Task:** R003 · **ACs:** AC-P11-05, AC-P11-06 · **Est:** 1 day

## Goal
Re-parse EVERY banked P10 completion with the relaxed grammar, re-score via the unchanged P4 oracle, write `rescoring-runs.jsonl`, and prove the change is scoped to the defect.

## Steps
1. Enumerate the full P10 submitted set from `results/scaling-runs-detail.jsonl` (every cell with a recorded completion; ≈155). Do NOT touch `infeasible_context` cells (no completion).
2. For each: run `bin/lab-regrammar` to extract the coordinate; if `accepted`, score with the unchanged P4 restore-validate (+ P4 lost-row rule on padded rows) to a verdict. Append the G6 row with `p10_outcome`, `outcome_changed`, `p10_verdict`, `verdict_class_changed`.
3. Run the CONSISTENCY gate: for every completion whose extracted coordinate is unchanged from P10, assert the re-scored verdict class equals the P10 verdict class. Any divergence halts pending an ADR (Article XX).
4. Run the SAFETY check: assert no row is `incorrect_corrupt`. If one appears, surface it (H3-R finding), do not suppress.
5. Compute the pre-registered re-run trigger (A4) and write `logs/review/R003/rerun-trigger.json`: for each H4/H1-R cell, evaluable replicate count and whether < 5.

## Acceptance tests
- **AC-P11-05:** completeness (all banked completions re-parsed) + consistency gate green. **Negative:** flip one unchanged-coordinate verdict in a scratch copy → gate catches it.
- **AC-P11-06:** no new `incorrect_corrupt`. **Negative:** inject a synthetic damage-retaining completion → scored `incorrect_corrupt` and surfaced.

## Review bundle
`rescoring-runs.jsonl` (+ SHA-256), the outcome-change table (how many parser-refusals became accepted, per model/scale), consistency report, safety report, `rerun-trigger.json`, both negative transcripts.
